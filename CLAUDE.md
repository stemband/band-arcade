# Band Arcade: notes for Claude

Mat Graham (middle school band director) owns this project. It's a set of mic-driven practice games for beginning band students, played on school iPads (Safari) and Chromebooks (Chrome) in practice rooms and at home. It's hosted as a static site on GitHub Pages.

## Hard rules
- **No build step, no npm dependencies, no frameworks.** Plain HTML/CSS/JS served as static files. Mat edits and deploys without tooling. The one vendored library is three.js **r149** (`shared/vendor/three.min.js` + MIT license), used only by the home page. It's pinned because r149 is the last release with a classic UMD `three.min.js`; later ones are modules-only, which breaks double-click testing.
- **Classic `<script>` tags, not ES modules.** Everything hangs off the `window.Arcade` namespace. Modules break when a page is opened from a local file, and Mat tests by double-clicking.
- **All links end in `index.html`** (e.g. `../index.html`, `ghost-notes/index.html`) so they work both locally and hosted. Build links with `Arcade.link(path)` so `?demo` carries through.
- **Never copy shared logic into a game.** Instruments and transpositions live only in `shared/instruments.js`, pitch detection only in `shared/pitch.js`, and so on. A fix to the engine must reach every game.
- **No audio while a game is listening to the microphone.** Sound is allowed on the arcade floor and select-player pages through `shared/sfx.js`, and must always respect the mute setting. A game that never uses the microphone (Note Ninja, Chime Heist, Ancient Ninja Scrolls, Button Masher) may use `sfx.js` too; a game that listens must never load it. The ONE exception is Neon Face-Off: every sound it plays is short (< 0.5 s) and mutes the detector while it plays (`Arcade.Pitch.suppress(ms)`), and the next player's reaction clock starts only after that window (`FACEOFF_RULES.suppressMs`; `sounds: false` makes it silent). Any other listening game stays silent.
- Games must work on iPad Safari. The mic and AudioContext start only from a tap, via `Arcade.requireMic(fn)`.
- Keep the student-facing copy plain and encouraging. Students are 11–14.

## Page flow
1. `index.html`, the arcade floor: students choose a GAME from a carousel of cabinets (◀ ▶ buttons, swipe, ←/→ keys, indicator lights, tap a side cabinet). No instruments here. START links to Select Player. The URL hash (`#ghost-notes`) says which cabinet is in front; game pages link back with it.
   The cabinets are drawn in 3D (`arcade3d.js`, three.js) when WebGL works, else in 2D (`shared/cabinets.js`). `?flat` forces 2D; `?keep3d` (testing only) disables the automatic slow-device fallback; `?fps` shows the average frame time.
2. `select-player/index.html?game=<id>` (`&players=2` for a two-player game: games.js `players: 2`; `Arcade.playerLink` adds it): a fighting-game character select. The game's marquee (small), "SELECT YOUR PLAYER", "CONTINUE AS <instrument>" (with its portrait) when one is saved, a big preview + PLAYER CARD (name, key · clef, first five, stars on this device via `store.starsForPlayer`, the horn's "Starting notes: F–C / C–G" toggle = `store.setHornStart`, and a SKINS button that opens the locker: equip per instrument, live preview, locked skins as silhouettes with their requirement), and the 15 instrument tiles (`Arcade.PLAYERS` order, 5 × 3; 3 columns on phones), tinted by family (woodwinds `--pink`, brass `--amber`, percussion `--cyan`). Tap highlights (pulsing outline + 1P marker), tap again or SELECT confirms; arrows move, Enter selects. Confirm calls `Arcade.store.setPlayer(memberId)`, flashes "PLAYER 1 READY", then goes to the game. After the members migration it shows `store.pending` (the old group's tiles dashed + "Pick your exact instrument!", or the Colored Tone Bells notice). Two-player: after Player 1 (cyan 1P marker; "PLAYER 1 READY"), "PLAYER 2 — PRESS START": Player 1's tile keeps its 1P marker, Player 2's highlight is magenta with a 2P marker, a CPU tile joins the grid, "Same opponent" replaces Continue, and the choice is saved with `store.setOpponent(memberId | 'cpu')` (its own horn setting `opponentHornStart`), never replacing Player 1's instrument. A bad or missing `?game=` goes home.
3. Game pages: `Arcade.requireInstrument(GAME_ID)` returns the saved player's GROUP, or sends students with no saved instrument (member) to Select Player for that game. `Arcade.mountTopbar(inst, extraHTML, GAME_ID)`: "← ARCADE" goes home (turned to this game), the instrument chip (tiny portrait + the member's `short` name) opens Select Player for this game.
- THE SAVED CHOICE IS AN INSTRUMENT MEMBER (`Arcade.store.player`: `'trumpet'`, `'oboe'`, `'horn'`…). Games never ask "Which instrument do you play?": the member IS the answer (`store.memberFor(group)` returns it, `Arcade.currentMember()` gives it). Behind the scenes it maps to its old player GROUP with **`Arcade.groupFor(memberId, {hornStart})`** (instruments.js; `store.instId` uses it), and every game keeps saving progress under the group id, so old stars never move. Always go member → group through that helper. Horn is one member in two groups (`hornF` / `hornC`), picked by `store.hornStart` ('F' default | 'C'). Colored Tone Bells is gone. The one-time `players-v1` migration in storage.js maps old saves (see README "Players and old saves").
- A one-instrument game sets `player: '<group id>'` (and `playerName`) in `games.js` (Chime Heist: `'bells'`); a game with no instrument sets `player: 'all'` (Ancient Ninja Scrolls; progress saved under inst id `'all'`, no label, no modes note). `Arcade.startLink(game, root)` then goes straight to the game (the floor's 2D and 3D START both use it), Select Player redirects there, the saved instrument is never changed, and the floor's hi-score reads that group. Such a game uses `Arcade.getInstrument(id)` instead of `requireInstrument`, and `mountTopbar(inst, extra, GAME_ID, {fixed: 'Bell Kit'})` shows a plain label instead of the instrument link. `noteModes: true` marks a note-reading game (the NOTES × ORDER picker; the floor shows its all-modes total).
- `players: 2` (Neon Face-Off) makes START and the chip open Select Player with `&players=2`.
- `byMember: true` (Button Masher, Neon Face-Off) saves progress under the MEMBER id (`trumpet`, `clarinet`…) of the saved player, and the floor's hi-score reads it. Every hi-score line names the player's member (`short`). `noPlay: {groups, members, label, game}` replaces the hi-score with a link to another game for instruments the game can't use (percussion → Chime Heist).

## Engine API (shared/)
- `Arcade.INSTRUMENTS`, `Arcade.currentInstrument()`. Each instrument (player group) has `notes` (written), `targetPc` (concert pitch classes), `writtenName(pc)`, `clef`, `t` (transposition), `concertLabel`, `shortName`, and `members`. Never change a group's `id`, first five notes or `t`: saved stars and links depend on them (the flute group's name lost "Colored Tone Bells" when that member was removed).
- Members (`inst.members`): the real instruments in a group, `{id, name, short (tile/chip label), family ('woodwind'|'brass'|'percussion'), chromatic: [lowest, highest written], sounds}`; `Arcade.PLAYERS` = the 15 member ids in Select Player order, `Arcade.memberById(id)`, `Arcade.groupsOf(id)`. `sounds` = exact semitones the instrument sounds BELOW written pitch (negative = higher; bells −24, tenor sax 14), octave included, always ≡ `t` mod 12. Ranges come from the **GMEA All-State Middle School Chromatic Scale sheets**; if GMEA changes a sheet, update `MEMBERS` in `instruments.js` (not a game). Helpers: `Arcade.getMember(inst, id)`, `Arcade.chromaticScale(member, {down})` (written notes with `midi` and `sounding`; sharps going up like the GMEA sheets, flats going down, end notes keep their given spelling), `Arcade.music.spell(midi, flats)`.
- `Arcade.Pitch.setInstrument(inst)`, `onFrame((reading, level, now) => …)` (~25×/s; `reading` is `null` or `{freq, midi, note, pc, cents}` with a concert `pc` and `note` = rounded SOUNDING midi), `onHeld((pc, now, note) => …)` (once per held note, `holdMs` = 280), `ignoreCurrent()`, `heldPc()`, `setSensitivity(0–100)`, `bars(level)`, `levelPct(level)`.
- `Arcade.Pitch.suppress(ms)`: hear nothing new for ms (a sound effect is playing); what is still sounding afterwards stays counted, so only a new attack fires. `Pitch.suppressedUntil`. `Pitch.instrument()` / `Pitch.range()` report what the detector is listening for (tests).
- `Arcade.Pitch.setRange(lowMidi, highMidi)` (Note Checker scale/chromatic modes, and games with a scale or Chromatic NOTES pool via `ModePicker.useRange`; First 5 never calls it): search a member's SOUNDING range, octave-exact holds (D4 then D5 fires twice), and a reading outside the range whose octave above/below is inside is reported in that octave (`reading.folded`), because built-in mics often hear low brass an octave off. For low ranges it averages samples first (÷2–4) so tuba E1 (41 Hz) costs less than a game's tuba range. `setRange(null)` restores the default. `?demo`: `Pitch.demoNote = <sounding midi>` "plays" a note.
- Scales (`shared/scales.js`, every game + the Note Checker + the home page): `Arcade.Scales.LIST` (`Bb`, `Eb`, `F`, `Ab`, `chrom`), `Scales.build(member, id)` → `{name, label ('Concert E♭ (your F Major)'), key, sig {type, count}, up, notes (up then down)}`, each note `{letter, acc, oct, midi (written), sounding, pc, show}` where `show` is how to draw it under the key signature. Written scales are transposed with the member's `sounds` and spelled in the written key (never mixed sharps/flats). The **`START` table** at the top of scales.js holds the written starting note for every member × scale; it should match the GMEA scale sheets, and a wrong-key entry falls back to the rule (B♭ = the first-five tonic; others = the tonic nearest that whose octave fits the GMEA range). `Scales.sequence(scale, count)` repeats the scale to fill a level; `Scales.progressKey(gameId, id)` = `'<gameId>:scale-<id>'`.
- Portraits (`shared/portraits.js`, loaded by every page with a top bar and by Select Player): the drawn fallback is `Arcade.portraitSVG(memberId, {size: 'big'|'tile'|'chip', color, glow, style: 'neon'|'line', cls, label})`, neon line art on a 100 × 100 grid built from parts (`tube` centerlines drawn as two glowing edges, `shape` outlines, `line`s, `ring`s); each instrument's signature color is a `--pt-<id>` token in theme.css. Color and style are options so a skin can restyle them; never hard-code a color in a part. The same drawing is used big, on tiles and in the chip.
- PORTRAIT IMAGES (Mat's artwork, `shared/portraits/`, mapping + how-to in its README.md): show a player's portrait ONLY with `Arcade.portraitHTML(memberId, {size, full, skin, label, cls, color})`, never an `<img>` of your own. It returns a square `.pt-box` (theme.css) with the SVG portrait underneath and the image on top, hidden until it loads; a missing or broken file tries the next candidate (`optimized/<name>.webp` if listed in `OPTIMIZED`, `<name>.png`, `<name>.webp`) and ends on the SVG, so a broken image never shows. `full: true` (the Select Player preview only) tries `<name>-full` first. `skin` ({color, acc}; left out = the instrument's equipped skin, `false` = none) draws the SKINS below and tries the drawn variants `<name>--<color>` / `<name>--<acc>` (and `-full--`) first; failed variant/-full URLs are remembered per tab in sessionStorage. `color` (recolored CPU rivals) or `'cpu'` = SVG only, no skin. File names are in `FILES` in portraits.js (member id → file name). Images are `object-fit: contain` on transparent backgrounds; markers (1P/2P) and outlines sit above them (`z-index`). An image over 250 KB or 1024 px gets a WebP copy in `shared/portraits/optimized/` (≤ 512 px; ≤ 1024 px tall for `-full`) listed in `OPTIMIZED`; the original is never touched, and replacing it means deleting its copy.
- SKINS (`shared/skins.js`, loaded right after portraits.js by EVERY page that shows a portrait; those pages also load `games.js`, which `allStars` needs for `byMember` games): one color skin + one accessory per instrument MEMBER, saved on the device (`store.skin(m)` / `setSkin(m, patch)`; shown ones in `store.skinsSeen(key)` / `markSkinsSeen`, key = member for star milestones, `'*'` for achievements). `Arcade.Skins`: `LIST` (the `SKINS` table: `{id (never change), kind 'color'|'acc', name, unlock, look | art}`), `ANCHORS` (accessory positions per instrument: `img`/`svg`/optional `full` × `head [x,y,w]`, `face [x,y,w,tilt]`, optional `back [x,y,w]`, all in percent of the square portrait; mirrored as a table in shared/portraits/README.md), `ACC_ART`, `isUnlocked(skin, member)`, `requirement(skin)`, `progress(skin, member)`, `milestone(skin)`, `equipped(member)` (a locked choice falls back to Classic Neon / none), `equip(member, {color}|{acc})`, `label(eq)` (alt text: "Trumpet, Flame skin, Crown"), `fresh(member)`, `announce(panel, {members, member})`, `catchUp(member)`, `refresh(member)`, `decorate()` (portraits.js's hook). UNLOCK RULES: `{always}`, `{stars: n}` = `store.allStars(member)` ≥ n (per instrument), `{game, level, stars, text}` = `store.bestLevelStars(game, level)` (any progress key of that game, any instrument) ≥ stars, `{game, badge: true}` = any Ancient Ninja Scrolls badge; achievements unlock for every instrument; a rule for a game missing from games.js is skipped. Rules are checked from saved progress (never only at the moment of a result), so old progress counts. EVERY RESULTS SCREEN calls `A.Skins.announce(panel)` after it shows (Chime Heist: `{members: ['bells'], member: 'bells'}`; Neon Face-Off: vs CPU only; the scrolls' Belt Exam badge panel too); Select Player calls `catchUp(store.player)` on load. Never show an UNLOCKED! card during play. Effects: CSS in theme.css "Skins" (`.sk-*`), drawn parts (flame aura, sparkles) in skins.js; tokens only; animation ONLY on `.pt-box-big` and never under reduced motion; image effects only once the picture loaded (`.pt-ok`), the SVG fallback just recolors (`svgColor`/`svgGlow`); a drawn variant sets `.pt-var-c` (effects off) / `.pt-var-a` (overlay off); Pixel redraws the loaded picture into a small canvas (`.pt-pix`). Portrait CSS must never style `.pt-box svg` descendants (the accessory is an `svg` too): use `.pt-box>svg.portrait`. `?demo&unlockall` previews everything (never saved, never announced).
- NOTE SEQUENCES (`shared/sequences.js`, on top of scales.js): THE way a note-reading game gets its notes. `Arcade.buildSequence({member, group, notes, order, level, count, pool})` -> `{items, pool, fit, sig, scale, name(pc), small}`; each item `{n (written note, key-correct spelling: answers use it), show (how to draw it), label, midi (written), sounding, pc}`. NOTES: `'first5'` (the group's first five; Horn's Starting notes pick the group) | `'Bb'|'Eb'|'F'|'Ab'` (the member's one-octave written scale from scales.js, 8 notes, same octave as scale mode) | `'chrom'` (the member's whole GMEA range). ORDER: `'random'` (bag shuffle: every pool note before any repeats, never the same pitch twice in a row; the level's `pool` below 5, i.e. level 1, uses the smaller pool: first three / the scale's first five / one octave from the first-five tonic; chromatic black keys spelled ♯ or ♭ at random) | `'order'` (up then down, then again from the second note; first5 = the five up and down, chrom = up in sharps, down in flats). Scale pools draw the key signature in both orders (`sig`, `show`); first5 and chrom draw accidentals, no key signature. Also `Arcade.progressKey(gameId, notes, order)`, `Arcade.progressKeys(gameId)` (all 12), `Arcade.NOTE_CHOICES`, `Arcade.ORDER_CHOICES`.
- MODE PICKER (`shared/mode-picker.js`, styles `.mp*` in theme.css): `Arcade.ModePicker.mount(el, {gameId, levels, onChange, group?, member?})` draws NOTES (six buttons, each with its stars for the chosen ORDER out of the game's `maxStars` from games.js) and ORDER (Random | Scale Order) plus a line explaining the choice; remembered per game (`store.noteMode`/`setNoteMode`; `memory: key` remembers it elsewhere, e.g. Neon Face-Off's `'neon-face-off:p1'`/`':p2'`; `stars: false` hides the star totals). `picker.state` = `{notes, order, member, group, scale, progressKey, label}`. Helpers: `ModePicker.sequence(state, L, lv)` (buildSequence for a level row), `levelText(state, L, lv, extraParts)` (the game's own blurb for First 5 + Random, else what the level plays + the game's parts), `hubCard(state)`, `useRange(state)`, `demoSpace(fn)`. Used by Ghost Notes, Note Storm, Note Ninja, Chime Heist (group/member = the bells) and Neon Face-Off (one per player, no stars); NOT by Button Masher, Ancient Ninja Scrolls or the Note Checker.
- PROGRESS KEYS for note-reading games (never rename; `KEY_OVERRIDES` in sequences.js keeps a game's older keys):

| NOTES | ORDER | Progress key | Notes |
|---|---|---|---|
| First 5 | Random | `<game>` | the original key: every star from before scales still counts here |
| First 5 | Scale Order | `<game>:order-first5` | new |
| Concert B♭ / E♭ / F / A♭ | Scale Order | `<game>:scale-Bb` … `:scale-Ab` | the original SCALES keys |
| Chromatic | Scale Order | `<game>:scale-chrom` (Chime Heist: `chime-heist:chromatic`) | the original keys |
| Concert B♭ / E♭ / F / A♭ | Random | `<game>:random-Bb` … `:random-Ab` | new |
| Chromatic | Random | `<game>:random-chromatic` (Chime Heist: `chime-heist:full`, its old FULL RANGE) | new (Chime Heist: kept) |

- `Arcade.requireMic(fn)` shows the mic prompt when needed, then runs `fn`.
- Links: `Arcade.link(path)` keeps the query string. `Arcade.linkTo(path, {game})` keeps `?demo` but sets or drops `?game=` (use it for links between pages). `Arcade.playerLink(gameId, root)`, `Arcade.homeLink(gameId, root)`; `root` is `'../'` from a game folder (the default) or `''` from the site root.
- Sound (`shared/sfx.js`, loaded ONLY by `index.html`, `select-player/` and mic-free games (`note-ninja/`, `chime-heist/`, `ancient-ninja-scrolls/`, `button-masher/`); never Ghost Notes, Note Storm or the Note Checker): `Arcade.Sfx.play('whoosh'|'coin'|'blip')`, `Arcade.Sfx.event(name)` (named events: `level-start`, `note-hit`, `note-wrong`, `note-missed`, `level-complete`, `level-failed`, `star-earned`, `new-high-score`, `tile-move`, `player-select`, `player-ready` (Select Player), `ninja-slash`, `ninja-combo`, `belt-earned`, `belt-diamond`, `tumbler-click`, `alarm-buzz`, `caught`, `vault-open`, `vault-unlocked`, `answer-right`, `answer-wrong`, `scroll-unroll`, `gong`, `test-ready`, `fight-start`, `key-press`, `special-move`, `combo-streak`, `rival-counter`, `ko`, and `skin-unlocked`, `skin-equip` (skins.js plays them only where sfx.js is loaded, and mutes the detector first with `Pitch.suppress` in Neon Face-Off), `select-<gameId>` which the floor's START plays; anything without its own sound falls back to the coin for `select-*`, else the blip), `Arcade.Sfx.allowAmbience(false)` (game pages: no room hum), `Arcade.Sfx.playThenGo(name, href)` (waits 300 ms, or goes straight away when muted), `Arcade.Sfx.mountControls(el, {ambience})` (SOUND and optionally AMBIENCE buttons), `Arcade.Sfx.bell(soundingMidi)` (a synthesized bell at that exact pitch, silent when muted; Chime Heist's bars, never replaced by files). There is no `sounds.js`: all events live in `EVENTS` in sfx.js and are listed in the README's Sounds table. All sounds are synthesized with Web Audio; the AudioContext starts on the first pointerdown/keydown, never on load. Settings: `Arcade.store.sfx`/`setSfx(on)` (default on), `Arcade.store.ambience`/`setAmbience(on)` (default off; plays only when sound is on).
- `Arcade.requireInstrument(gameId)`: the saved instrument, or redirect to Select Player (returns null).
- Cabinets (`shared/cabinets.js` + `shared/cabinets.css`): `Arcade.cabinetHTML(game, {href})`, `Arcade.marqueeHTML(game)`, `Arcade.trimClasses(game)`, `Arcade.cabinetOf(game)` (settings with defaults), `Arcade.setAttract(cabEl, game)` (only the front cabinet animates).
- `Arcade.staffSVG(clef, items, {fit, label, width, captions, keySig})` (key signatures in the standard positions, any count, treble or bass; start notes `Arcade.keySigWidth(sig)` further right; `n.natural` draws ♮), `Arcade.noteGlyph(clef, {n, x, caption}, capY)` (one note, for games that move notes on their own layer), `Arcade.noteY(clef, n)`, `Arcade.fiveNoteStaff(inst, colorFor)`, `Arcade.colorNote(id, color)`, `Arcade.ghostSVG(text, cls)`, `Arcade.ninjaSVG({belt, cls, label})` (the Note Ninja mascot; colors resolved from tokens so it also works as a canvas image), `Arcade.starStr(n)`, `Arcade.mountTopbar(inst, extraHTML, gameId, {fixed})`, `Arcade.symbolSVG(id, label)` / `Arcade.symbolName(id)` / `Arcade.SYMBOL_IDS` (music symbols on a short staff: treble-clef, bass-clef, fermata, repeat, measure-repeat, accent).
- Belts (`shared/belts.js`): `Arcade.BELTS` = the 10 Band Ninja belts `{rank, name, color, sparkle}`, `Arcade.belt(rankOrName)`. The only place belt names/colors live; Note Ninja's levels.js matches by `name`, Ancient Ninja Scrolls uses ranks 3–10.
- `Arcade.store`: `player`/`setPlayer(memberId)`, `instId` (the player's group), `hornStart`/`setHornStart('F'|'C')`, `pending`, `opponent`/`setOpponent(memberId | 'cpu')` + `opponentHornStart`/`setOpponentHornStart` (Player 2 in two-player games), **`allStars(instrument, gameId?)`** (THE star total: every progress key (all NOTES × ORDER combinations, every game's modes) for an instrument (a member id, or a player id like `'bells'`), for one game or all games; use it wherever a total is shown or checked: the floor's hi-score, the player card, future unlocks; `starsForPlayer(m)` = `allStars(m)`), `noteMode(gameId)`/`setNoteMode(gameId, {notes, order})` (reads choices saved by the old picker too), `sens`, `sfx`, `ambience`, `checkerMode` ('five'|'Bb'|'Eb'|'F'|'Ab'|'full'), `memberFor(groupId)`/`setMember(groupId, id)`, `level(game, inst, lvl)`, `setLevel(game, inst, lvl, {stars, best})`, `totalStars(game, inst)`, `hasProgress(game, inst)`, `gameData(gameId)` + `saveGameData(gameId)` (a game's own extra records, kept out of `games`), one-time moves in `migrate()` flagged in `data.migrated`. Progress shape: `games[gameKey][instId][level] = {stars, best}`. Note-reading games use the PROGRESS KEYS table above. The home page's hi-score shows `allStars` for the game ("all modes") and "Modes played: n of 12" (games.js `noteModes: true`).
- `Arcade.DEMO` is true with `?demo`. Keys 1–5 fake the five notes, and games should unlock all levels.

## Adding a game
Make a new folder with `index.html` (same shared script tags as `ghost-notes/index.html`, including `games.js`, `scales.js`, `sequences.js` and `mode-picker.js`), `style.css` and `game.js`. Start `game.js` with `requireInstrument` + `mountTopbar(inst, '', GAME_ID)`. Load `portraits.js` + `skins.js` + `games.js`, and call `A.Skins.announce($('results').querySelector('.panel'))` whenever the results screen shows. A note-reading game gets its notes ONLY from `sequences.js` and its mode UI ONLY from `mode-picker.js`: mount `Arcade.ModePicker` on the level screen, build each level with `ModePicker.sequence(picker.state, L, lv)`, draw items' `show` with the result's `sig` and `fit`, check answers against `n` (or `pc`/`sounding` for the mic), save with `picker.state.progressKey`, and set `noteModes: true` in games.js. Never write a shuffle or scale loop in a game. First 5 + Random must behave exactly like the game always has (levels.js `pool: 3` on level 1). Add it to `shared/games.js` (`maxStars` = levels × 3, or 0) with a main `color` (`'pink'|'cyan'|'yellow'`) and a `cabinet` entry. Reuse `theme.css` components (`.stage`, `.hear`, `.overlay/.panel`, `.btn-*`).
- Cabinets: each game's look is its `cabinet` field in `games.js` (`shape`, `trim`, `trim2`, `marquee`, `kicker`, `screen`; all optional, missing or unknown values fall back to a classic cabinet). The parts it picks from live in `shared/cabinets.js` (`SHAPES` silhouettes on a 300 × 600 grid, `SCREENS` attract loops) and `shared/cabinets.css` (trim colors, marquee lettering, screen styles). Give a new game its own silhouette/screen rather than reusing another game's whole look. Never let a missing cabinet entry break the home page.
- 3D cabinets: `cabinet3d` in `games.js` (`profile`, `trim`, `trim2`, `body`; all optional, defaults come from the 2D `cabinet`, so the two views always match). `arcade3d.js` holds `PROFILES` (side-view points extruded into the body, with anchors for marquee, screen, panel, door, START and a topper: `peak`/`dome`/`fins`/`pagoda`/`vault`/`gate`/`vs`; `dial: true` = a round safe door; `twoPlayer: true` = two joysticks and two sets of buttons), the canvas-texture marquees and attract screens (canvas versions of `SCREENS`, same loops), and the scene. `arcade.js` owns all controls and HTML; a view (2D or 3D) implements `place(cur, instant)`, `pick(event)`, `startLink`, `destroy()`. The 3D canvas is decoration (`aria-hidden`); START is a real `<a>` positioned over the front cabinet, and it does not follow the sway.
- 3D performance rules: render only while something moves (turn, sway, front attract screen), ≤ 30 fps when idle, stop when the tab is hidden; pixel ratio ≤ 1.5; no post-processing (glow = additive planes and fat translucent tubes; reflection = the ring drawn upside down under a see-through floor, without small parts or far cabinets); average frame > 40 ms over 3 s → pixel ratio 1, no haze, no sway; still slow → 2D. `Arcade.Floor3D.stats()` reports frame times and draw calls. Colors come from the theme tokens (`getComputedStyle`), never hard-coded.
- The arcade floor look: a dark 1980s arcade at night: haze, neon sign (Monoton, `--neon-font`), cabinets glowing down an aisle with light pooling on the floor. ## Note Ninja (`note-ninja/`)

The right answer is the note's real name, key signature included (a B in F major is B♭, in Random and Scale Order alike), spelled as shown (C♯ ≠ D♭). Answer pad: ♭ ♮ ♯ act as a Shift for the next letter (♮ default, resets after each letter; shown only when the level's notes have any accidentals), then A–G. ## Ancient Ninja Scrolls (`ancient-ninja-scrolls/`)

## Button Masher (`button-masher/`)
- Fingering / slide-position trainer as a neon versus fighting game. NO microphone (never load `pitch.js` or `mic-gate.js`); loads `sfx.js`. No NOTES × ORDER picker: its 8 rivals ARE the modes (first 3, first 5, the four concert scales from `Scales.build(member, id).up`, then all four mixed), all under the plain key `button-masher`.
- Uses the saved player (`requireInstrument` + `Arcade.currentMember()`). Progress is keyed by MEMBER: `setLevel('button-masher', member.id, rival 1–8, {stars, best})` (`byMember: true` in games.js). Percussion (`bells`) gets "Percussion: try Chime Heist!" instead of a diagram, in the game and on the floor (`noPlay`).
- `fingerings.js` is THE fingering table (`MASHER_FINGERINGS[memberId] = {diagram, notes: {'Bb4': [primary, alternates…]}}`): brass `'1-3'`, `'0'`, horn trigger `'T1-2'`, 4th valve `'4'`; trombone positions `[1, 6]`; woodwinds = the diagram's key ids separated by spaces (`'|'` ignored, `'1h'` = half-hole). A combo is right only when the pressed keys EXACTLY match one entry. To fix a fingering, edit that list (primary first); every note used by rivals 1–8 must be listed for every member (a missing note or unknown key id warns in the console). Its top comment lists the fingerings to verify against the 6th Grade Honor Band charts; keep that list current.
- `diagrams.js` draws each family (`flute`, `oboe`, `clarinet`, `sax`, `bassoon`, `trumpet`, `horn`, `euph`, `tuba`, `trombone`) as SVG with real tappable keys (pointerdown). - Rivals in `levels.js` (`MASHER_RIVALS`: name, look, colors, taunt, pool, notes, health, time, showName, hint); rules in `MASHER_RULES`. Stars: 3 = no mistakes (wrong or timeout), 2 = 1–2, 1 = won. Cartoon only: energy blasts, a "boing" counter, dizzy stars; no weapons or injury. The fighter and the rivals are original drawings in `game.js`.
- CHART view (rival screen only, never during a match) shows every note with its primary fingering drawn and alternates listed.

## Neon Face-Off (`neon-face-off/`)
- Two-player air hockey played with instruments, one device, one microphone, turn-based. Player 1 cyan, Player 2 magenta (`--pink`). Player 2 is `store.opponent`: another member, or `'cpu'` (the ladder). Landscape: P1 left, P2 right; portrait: P2 on top (its panel rotated 180° to face them), P1 at the bottom. The table is a canvas (requestAnimationFrame, cheap shadows/gradients, dpr ≤ 1.5); reduced motion = no trail, no shake, no pulse.
- MICROPHONE: only the active player's target counts. Each turn: `Pitch.setInstrument(group)`, their range (`setRange(member range)` for scale/chromatic pools, `null` for First 5), `ignoreCurrent()`; a target never shares its concert pitch class with the note the other player just played. Every sound calls `Pitch.suppress(RULES.suppressMs)` and the receiver's note (and clock) appears only after it. The CPU plays silently.
- Notes: `Arcade.buildSequence` per player (their own member, NOTES × ORDER from their own picker, Rookie = the smaller level-1 pool). Strike power from reaction (note shown → note registered): `FACEOFF_RULES.power` (SMASH! / POWER / GOOD / WEAK) × a rally base that shrinks each return; a shot never gives the receiver less than their difficulty's window (+ `suppressMs`). A timeout = the other player scores; `serve: 'loser'` (the player scored on serves) or `'alternate'`. Wrong note: "That's D" in the player's written pitch, time keeps running.
- `levels.js`: `FACEOFF_RIVALS` (8 CPU rivals: name, color, plays (an instrument id for its portrait), reaction [min, max] s, accuracy), `FACEOFF_DIFFICULTY` (Rookie 4 s, Pro 2.5 s, All-Star 1.5 s), `FACEOFF_RULES`. Stars vs CPU: win 1, win by 4+ 2, shutout 3; saved `setLevel('neon-face-off', Player 1's member id, rival, {stars, best})` (`byMember`). Two-player matches: no stars; `store.gameData('neon-face-off')` = `{settings: {p1: {diff}, p2: {diff}, points, rival}, h2h: {'<p1 member>><p2 member>': {p1, p2}}}`.
- `?demo`: every rival unlocked; hold Space = the active player's note (press later = slower), W = a wrong note.

## Note Checker
- Modes FIRST 5 | B♭ | E♭ | F | A♭ | CHROMATIC (stored as 'five', 'Bb'…'Ab', 'full'). Scale modes show the scale up and down with its key signature; a held pitch lights the first dark place with that pitch, octave-exact, "11 of 15 notes".
- FIRST 5 NOTES: the original checker (letter names, any octave). CHROMATIC (FULL RANGE): the member's whole chromatic scale on wrapped staff rows (≥ 50 px per note so accidentals never touch), each note captioned.
- The octave rule: a note lights gold only when held in the octave written on the staff (exact sounding pitch via `sounds`). A same-letter note in another octave never counts; if the student replays a found note while its other octave is still missing, show "That's a D, but an octave lower. Try the higher one." Readings an octave outside the whole range are folded in by the pitch engine (mic error), so they do count.
- The note being heard gets a glowing outline; "Going down" shows the same pitches descending with flats (one set of found notes). `?demo` in full range: ↑/↓ pick a note, hold Space to play it, Shift+Space an octave low.

## Detector tuning (shared/pitch.js)
YIN with threshold 0.15, clarity ≥ 0.8, loudness gate from the sensitivity slider, ±0.65-semitone hysteresis, 110 ms release gap. Per-instrument search range comes from `range` in `instruments.js` (min × 0.78, max × 2.3). Change these carefully and note why in the commit message.
