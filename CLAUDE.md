# Band Arcade: notes for Claude

Mat Graham (middle school band director) owns this project. It's a set of mic-driven practice games for beginning band students, played on school iPads (Safari) and Chromebooks (Chrome) in practice rooms and at home. It's hosted as a static site on GitHub Pages.

## Hard rules
- **No build step, no npm dependencies, no frameworks.** Plain HTML/CSS/JS served as static files. Mat edits and deploys without tooling. The one vendored library is three.js **r149** (`shared/vendor/three.min.js` + MIT license), used only by the home page. It's pinned because r149 is the last release with a classic UMD `three.min.js`; later ones are modules-only, which breaks double-click testing.
- **Classic `<script>` tags, not ES modules.** Everything hangs off the `window.Arcade` namespace. Modules break when a page is opened from a local file, and Mat tests by double-clicking.
- **All links end in `index.html`** (e.g. `../index.html`, `ghost-notes/index.html`) so they work both locally and hosted. Build links with `Arcade.link(path)` so `?demo` carries through.
- **Never copy shared logic into a game.** Instruments and transpositions live only in `shared/instruments.js`, pitch detection only in `shared/pitch.js`, and so on. A fix to the engine must reach every game.
- **No audio while a game is listening to the microphone.** Sound is allowed on the arcade floor and select-player pages through `shared/sfx.js`, and must always respect the mute setting. A game that never uses the microphone (Note Ninja, Chime Heist, Ancient Ninja Scrolls, Button Masher) may use `sfx.js` too; a game that listens must never load it.
- Games must work on iPad Safari. The mic and AudioContext start only from a tap, via `Arcade.requireMic(fn)`.
- Keep the student-facing copy plain and encouraging. Students are 11–14.

## Page flow
1. `index.html`, the arcade floor: students choose a GAME from a carousel of cabinets (◀ ▶ buttons, swipe, ←/→ keys, indicator lights, tap a side cabinet). No instruments here. START links to Select Player. The URL hash (`#ghost-notes`) says which cabinet is in front; game pages link back with it.
   The cabinets are drawn in 3D (`arcade3d.js`, three.js) when WebGL works, else in 2D (`shared/cabinets.js`). `?flat` forces 2D; `?keep3d` (testing only) disables the automatic slow-device fallback; `?fps` shows the average frame time.
2. `select-player/index.html?game=<id>`: the game's marquee, "CONTINUE AS <instrument>" when one is saved, then the 10 instrument tiles. Choosing calls `Arcade.store.setInstId` and goes straight to the game. A bad or missing `?game=` goes home.
3. Game pages: `Arcade.requireInstrument(GAME_ID)` sends students with no saved instrument to Select Player for that game. `Arcade.mountTopbar(inst, extraHTML, GAME_ID)`: "← ARCADE" goes home (turned to this game), the instrument chip opens Select Player for this game.
- A one-instrument game sets `player: '<group id>'` (and `playerName`) in `games.js` (Chime Heist: `'bells'`); a game with no instrument sets `player: 'all'` (Ancient Ninja Scrolls; progress saved under inst id `'all'`, no label, no Scales note). `Arcade.startLink(game, root)` then goes straight to the game (the floor's 2D and 3D START both use it), Select Player redirects there, the saved instrument is never changed, and the floor's hi-score reads that group. Such a game uses `Arcade.getInstrument(id)` instead of `requireInstrument`, and `mountTopbar(inst, extra, GAME_ID, {fixed: 'Bell Kit'})` shows a plain label instead of the instrument link. `modeKeys` (e.g. `['full', 'scale-Bb', …]`) lists its other progress keys for the floor's "Other modes: n of 6 started" (`[]` = show none).
- `byMember: true` (Button Masher) saves progress under the MEMBER id (`trumpet`, `clarinet`…) chosen for "Which instrument do you play?", and the floor's hi-score reads that member (hidden until one is chosen). `noPlay: {groups, members, label, game}` replaces the hi-score with a link to another game for instruments the game can't use (percussion → Chime Heist).

## Engine API (shared/)
- `Arcade.INSTRUMENTS`, `Arcade.currentInstrument()`. Each instrument (player group) has `notes` (written), `targetPc` (concert pitch classes), `writtenName(pc)`, `clef`, `t` (transposition), `concertLabel`, `shortName`, and `members`. Never change a group's `id`, `name`, first five notes or `t`: saved stars and links depend on them.
- Members (`inst.members`, Note Checker FULL RANGE only; games use the first five notes): the real instruments in a group, `{id, name, chromatic: [lowest, highest written], sounds}`. `sounds` = exact semitones the instrument sounds BELOW written pitch (negative = higher; bells −24, tenor sax 14), octave included, always ≡ `t` mod 12. Ranges come from the **GMEA All-State Middle School Chromatic Scale sheets**; if GMEA changes a sheet, update `MEMBERS` in `instruments.js` (not a game). Helpers: `Arcade.getMember(inst, id)`, `Arcade.chromaticScale(member, {down})` (written notes with `midi` and `sounding`; sharps going up like the GMEA sheets, flats going down, end notes keep their given spelling), `Arcade.music.spell(midi, flats)`.
- `Arcade.Pitch.setInstrument(inst)`, `onFrame((reading, level, now) => …)` (~25×/s; `reading` is `null` or `{freq, midi, note, pc, cents}` with a concert `pc` and `note` = rounded SOUNDING midi), `onHeld((pc, now, note) => …)` (once per held note, `holdMs` = 280), `ignoreCurrent()`, `heldPc()`, `setSensitivity(0–100)`, `bars(level)`, `levelPct(level)`.
- `Arcade.Pitch.setRange(lowMidi, highMidi)` (Note Checker scale/chromatic modes, and games in SCALES mode via `Modes.useRange`; RANDOM mode never calls it): search a member's SOUNDING range, octave-exact holds (D4 then D5 fires twice), and a reading outside the range whose octave above/below is inside is reported in that octave (`reading.folded`), because built-in mics often hear low brass an octave off. For low ranges it averages samples first (÷2–4) so tuba E1 (41 Hz) costs less than a game's tuba range. `setRange(null)` restores the default. `?demo`: `Pitch.demoNote = <sounding midi>` "plays" a note.
- Scales (`shared/scales.js`, every game + the Note Checker + the home page): `Arcade.Scales.LIST` (`Bb`, `Eb`, `F`, `Ab`, `chrom`), `Scales.build(member, id)` → `{name, label ('Concert E♭ (your F Major)'), key, sig {type, count}, up, notes (up then down)}`, each note `{letter, acc, oct, midi (written), sounding, pc, show}` where `show` is how to draw it under the key signature. Written scales are transposed with the member's `sounds` and spelled in the written key (never mixed sharps/flats). The **`START` table** at the top of scales.js holds the written starting note for every member × scale; it should match the GMEA scale sheets, and a wrong-key entry falls back to the rule (B♭ = the first-five tonic; others = the tonic nearest that whose octave fits the GMEA range). `Scales.sequence(scale, count)` repeats the scale to fill a level; `Scales.progressKey(gameId, id)` = `'<gameId>:scale-<id>'`.
- `Arcade.Modes.memberPick(el, inst, onPick, why)`: the "Which instrument do you play?" question on its own (same saved setting), for a game without RANDOM NOTES / SCALES.
- Game modes (`shared/modes.js`): `Arcade.Modes.mount(el, {gameId, inst, levels, onChange, modes, scales, fixed, keyFor, member})` draws RANDOM NOTES / SCALES, the "Which instrument do you play?" question (same saved setting as the Note Checker) and the scale buttons with star totals; `picker.state` = `{mode, scale, member, progressKey, ready}`. Also `Modes.hubCard`, `Modes.nameFor(inst, scale)` (key-correct note names), `Modes.useRange(state)` (member's full range in SCALES, default in RANDOM), `Modes.demoSpace(fn)`. The optional fields are for games with other modes (defaults = RANDOM NOTES / SCALES exactly as before): `modes` = `[{id, label}]` buttons (4 → a 4-wide toggle), `scales` = which scale ids to offer, `fixed` = `{modeId: scaleId}` for a mode that is one scale (Chime Heist's CHROMATIC = `'chrom'`), `keyFor(mode, scaleId)` = the progress key, `member` = a fixed member (hides "Which instrument do you play?").
- `Arcade.requireMic(fn)` shows the mic prompt when needed, then runs `fn`.
- Links: `Arcade.link(path)` keeps the query string. `Arcade.linkTo(path, {game})` keeps `?demo` but sets or drops `?game=` (use it for links between pages). `Arcade.playerLink(gameId, root)`, `Arcade.homeLink(gameId, root)`; `root` is `'../'` from a game folder (the default) or `''` from the site root.
- Sound (`shared/sfx.js`, loaded ONLY by `index.html`, `select-player/` and mic-free games (`note-ninja/`, `chime-heist/`, `ancient-ninja-scrolls/`, `button-masher/`); never Ghost Notes, Note Storm or the Note Checker): `Arcade.Sfx.play('whoosh'|'coin'|'blip')`, `Arcade.Sfx.event(name)` (named events: `level-start`, `note-hit`, `note-wrong`, `note-missed`, `level-complete`, `level-failed`, `star-earned`, `new-high-score`, `ninja-slash`, `ninja-combo`, `belt-earned`, `belt-diamond`, `tumbler-click`, `alarm-buzz`, `caught`, `vault-open`, `vault-unlocked`, `answer-right`, `answer-wrong`, `scroll-unroll`, `gong`, `test-ready`, `fight-start`, `key-press`, `special-move`, `combo-streak`, `rival-counter`, `ko`, and `select-<gameId>` which the floor's START plays; anything without its own sound falls back to the coin for `select-*`, else the blip), `Arcade.Sfx.allowAmbience(false)` (game pages: no room hum), `Arcade.Sfx.playThenGo(name, href)` (waits 300 ms, or goes straight away when muted), `Arcade.Sfx.mountControls(el, {ambience})` (SOUND and optionally AMBIENCE buttons), `Arcade.Sfx.bell(soundingMidi)` (a synthesized bell at that exact pitch, silent when muted; Chime Heist's bars, never replaced by files). There is no `sounds.js`: all events live in `EVENTS` in sfx.js and are listed in the README's Sounds table. All sounds are synthesized with Web Audio; the AudioContext starts on the first pointerdown/keydown, never on load. Settings: `Arcade.store.sfx`/`setSfx(on)` (default on), `Arcade.store.ambience`/`setAmbience(on)` (default off; plays only when sound is on).
- `Arcade.requireInstrument(gameId)`: the saved instrument, or redirect to Select Player (returns null).
- Cabinets (`shared/cabinets.js` + `shared/cabinets.css`): `Arcade.cabinetHTML(game, {href})`, `Arcade.marqueeHTML(game)`, `Arcade.trimClasses(game)`, `Arcade.cabinetOf(game)` (settings with defaults), `Arcade.setAttract(cabEl, game)` (only the front cabinet animates).
- `Arcade.staffSVG(clef, items, {fit, label, width, captions, keySig})` (key signatures in the standard positions, any count, treble or bass; start notes `Arcade.keySigWidth(sig)` further right; `n.natural` draws ♮), `Arcade.noteGlyph(clef, {n, x, caption}, capY)` (one note, for games that move notes on their own layer), `Arcade.noteY(clef, n)`, `Arcade.fiveNoteStaff(inst, colorFor)`, `Arcade.colorNote(id, color)`, `Arcade.ghostSVG(text, cls)`, `Arcade.ninjaSVG({belt, cls, label})` (the Note Ninja mascot; colors resolved from tokens so it also works as a canvas image), `Arcade.starStr(n)`, `Arcade.mountTopbar(inst, extraHTML, gameId, {fixed})`, `Arcade.symbolSVG(id, label)` / `Arcade.symbolName(id)` / `Arcade.SYMBOL_IDS` (music symbols on a short staff: treble-clef, bass-clef, fermata, repeat, measure-repeat, accent).
- Belts (`shared/belts.js`): `Arcade.BELTS` = the 10 Band Ninja belts `{rank, name, color, sparkle}`, `Arcade.belt(rankOrName)`. The only place belt names/colors live; Note Ninja's levels.js matches by `name`, Ancient Ninja Scrolls uses ranks 3–10.
- `Arcade.store`: `instId`, `sens`, `sfx`, `ambience`, `checkerMode` ('five'|'Bb'|'Eb'|'F'|'Ab'|'full'), `memberFor(groupId)`/`setMember(groupId, id)`, `gameMode(gameId)`/`setGameMode(gameId, {mode, scale})`, `level(game, inst, lvl)`, `setLevel(game, inst, lvl, {stars, best})`, `totalStars(game, inst)`, `hasProgress(game, inst)`, `gameData(gameId)` + `saveGameData(gameId)` (a game's own extra records, kept out of `games`), one-time moves in `migrate()` flagged in `data.migrated`. Progress shape: `games[gameKey][instId][level] = {stars, best}`. RANDOM NOTES uses the plain game id (existing stars never move); SCALES uses `'<gameId>:scale-<id>'` (e.g. `ghost-notes:scale-Eb`). The home page's hi-score counts only the plain game id, plus "Scales: n of 5 started".
- `Arcade.DEMO` is true with `?demo`. Keys 1–5 fake the five notes, and games should unlock all levels.

## Adding a game
Make a new folder with `index.html` (same shared script tags as `ghost-notes/index.html`, including `scales.js` and `modes.js`), `style.css` and `game.js`. Start `game.js` with `requireInstrument` + `mountTopbar(inst, '', GAME_ID)`. Every game has RANDOM NOTES and SCALES: mount `Arcade.Modes` on the level screen, build each level's notes from the first five (random) or `Scales.sequence` (scales: in order, up then down), draw with `keySig`, and save with `picker.state.progressKey`. RANDOM mode must behave exactly like the game always has. Add it to `shared/games.js` (`maxStars` = levels × 3, or 0) with a main `color` (`'pink'|'cyan'|'yellow'`) and a `cabinet` entry. Reuse `theme.css` components (`.stage`, `.hear`, `.overlay/.panel`, `.btn-*`).
- Cabinets: each game's look is its `cabinet` field in `games.js` (`shape`, `trim`, `trim2`, `marquee`, `kicker`, `screen`; all optional, missing or unknown values fall back to a classic cabinet). The parts it picks from live in `shared/cabinets.js` (`SHAPES` silhouettes on a 300 × 600 grid, `SCREENS` attract loops) and `shared/cabinets.css` (trim colors, marquee lettering, screen styles). Give a new game its own silhouette/screen rather than reusing another game's whole look. Never let a missing cabinet entry break the home page.
- 3D cabinets: `cabinet3d` in `games.js` (`profile`, `trim`, `trim2`, `body`; all optional, defaults come from the 2D `cabinet`, so the two views always match). `arcade3d.js` holds `PROFILES` (side-view points extruded into the body, with anchors for marquee, screen, panel, door, START and a topper: `peak`/`dome`/`fins`/`pagoda`/`vault`/`gate`/`vs`; `dial: true` = a round safe door; `twoPlayer: true` = two joysticks and two sets of buttons), the canvas-texture marquees and attract screens (canvas versions of `SCREENS`, same loops), and the scene. `arcade.js` owns all controls and HTML; a view (2D or 3D) implements `place(cur, instant)`, `pick(event)`, `startLink`, `destroy()`. The 3D canvas is decoration (`aria-hidden`); START is a real `<a>` positioned over the front cabinet, and it does not follow the sway.
- 3D performance rules: render only while something moves (turn, sway, front attract screen), ≤ 30 fps when idle, stop when the tab is hidden; pixel ratio ≤ 1.5; no post-processing (glow = additive planes and fat translucent tubes; reflection = the ring drawn upside down under a see-through floor, without small parts or far cabinets); average frame > 40 ms over 3 s → pixel ratio 1, no haze, no sway; still slow → 2D. `Arcade.Floor3D.stats()` reports frame times and draw calls. Colors come from the theme tokens (`getComputedStyle`), never hard-coded.
- The arcade floor look: a dark 1980s arcade at night: haze, neon sign (Monoton, `--neon-font`), cabinets glowing down an aisle with light pooling on the floor. Carousel turns stay under 0.5 s; only the front cabinet's screen animates; `prefers-reduced-motion` gives a plain fade and no attract loops. At phone width only one cabinet shows, arrows beside it. Nothing may scroll sideways.
- Keep the neon arcade look: a near-black arcade floor (`--floor`, `--floor-2`, `--floor-3`, `--deep`) lit by neon `--pink`, `--cyan` and `--yellow` (each with `-hi`/`-ink` variants and a `--glow-*` shadow). Every color is a token in `shared/theme.css` (cabinets also use `--purple`, `--amber`, `--green` and the `--cab-*` woodwork tokens); don't hard-code colors in a game. Neon is for titles, borders, glows and short labels; long text uses `--text-hi`/`--text-lo` so it meets WCAG AA. The staff `.stage` is a light "screen" (`--screen`, `--ink`) in a cyan neon frame, so notation stays crisp. Titles use the display font (`--display`, Bungee); body text stays Atkinson Hyperlegible (`--text`). Marquee fonts (`GN Haunt`, `GN Pixel`, `GN Shade`, `GN Neon`) are subset .woff2 files in `shared/fonts/` covering only Latin letters, digits and a little punctuation: signs only, never body text. Keep motion light (no blur filters) and turn it off under `prefers-reduced-motion`. The older names (`--gold`, `--night-2`, `--bone`, `--mist`, `--coral`…) are aliases of the new tokens.

## Note Ninja (`note-ninja/`)
- Note identification with NO microphone: never load `pitch.js` or `mic-gate.js` there, never ask for the mic. It loads `sfx.js` and plays the named events.
- RANDOM NOTES / SCALES like every game (`Arcade.Modes`). The right answer is the note's real name, key signature included (a B in F major is B♭), spelled as shown (C♯ ≠ D♭). Answer pad: ♭ ♮ ♯ act as a Shift for the next letter (♮ default, resets after each letter; shown only when the mode's notes have any accidentals), then A–G. Keys A–G and 1/2/3 on Chromebooks. `?demo` shows the answer under the buttons.
- Belts = levels in `note-ninja/levels.js` (`NINJA_BELTS`: name (one of `shared/belts.js`, which supplies the color and sparkle), count, time, guides, onStaff for read-ahead, pool, `relabel: false` = the letter buttons don't show ♭/♯ after the Shift). They are Mat's 10 Band Ninja ranks, in order: White, Yellow, Orange, Green, Blue, Purple, Red, Brown, Black, Diamond (`maxStars` 30). Belt colors are `--belt-*` tokens in theme.css. Progress is saved by belt number, so never reorder or insert belts without a one-time migration in `storage.js` `migrate()` (flagged in `data.migrated`; `ninja-10-belts` moved old 8 → 9 and 7 → 8 when Red was added). Unlocking = the previous belt has a star, or the belt itself already has stars. Scoring and stars are in `NINJA_RULES`. Progress: `note-ninja` (random) and `note-ninja:scale-<id>`.
- The staff stays large and still on the scroll; motion (ninja strike, target split, scroll shake on a wrong answer) is short and off under reduced motion. The ninja is original (white gi, red headband, bokken, face showing): don't turn it into a masked or franchise-looking ninja.

## Chime Heist (`chime-heist/`)
- Mallet keyboard trainer with NO microphone (never load `pitch.js` or `mic-gate.js`). Always the `bells` group / `bells` member (written G3–C6, `sounds` −24): `player: 'bells'` in games.js; never touch `store.instId`. Loads `sfx.js`: `Sfx.bell(written + 24)` on every strike, right or wrong, plus the heist events.
- The bell kit: every bar is a `<button class="bar">` with `data-midi` (written), naturals below, accidentals raised in 2/3 groups, shorter as pitch rises; strikes on `pointerdown` (multi-touch safe, `touch-action: manipulation`); keyboard ←/→ along a row, ↑/↓ between rows, Enter/Space strike. Phones in portrait (≤ 599 px wide) get the "Turn your device sideways" screen; iPad portrait/landscape and 1366 × 768 must fit with no scrolling.
- Modes: `random` (FIRST FIVE, key `chime-heist`), `full` (`chime-heist:full`), `scales` (B♭ E♭ F A♭, `chime-heist:scale-<id>`), `chrom` (`chime-heist:chromatic`), all saved under inst `bells`. Correct = the exact written midi (octave included; a same-letter bar in another octave is "Right note, wrong octave!" and a mistake). Scale notes' `midi` already includes the key signature.
- Vaults = levels in `chime-heist/levels.js` (`HEIST_VAULTS`: name, treasure, count, time, labels `all|faded|c|none`, onScreen for read-ahead, alarm segments, pool). Scoring/stars in `HEIST_RULES`. Mistakes and timeouts each add an alarm segment; a full meter = caught = 0 stars. Keep it a playful cartoon heist: no weapons, nobody hurt.

## Ancient Ninja Scrolls (`ancient-ninja-scrolls/`)
- Band Ninja vocabulary trainer, Ranks 3–10. NO microphone and NO instrument (never load `pitch.js`/`mic-gate.js`; `player: 'all'`). Loads `belts.js` and `sfx.js`.
- `vocab.js` is Mat's source for the vocab tests: `VOCAB_BANKS` (word banks exactly as printed), `VOCAB_PASS` (max missed: Orange 0, Green 2, Blue–Diamond 3), `VOCAB` items `{id, rank, prompt (with ___), answer, type 'word'|'symbol', show?, tip?}`, `SCROLL_RULES`. Never change an item's `id` (saved progress uses it); every word answer must equal a bank word exactly, accents included (Più, L'istesso). Keep 15 items per rank.
- Modes: Train (4 choices from the belt's bank, every other question flipped, misses come back until right twice; stars 1 = round, 2 = 90% first try, 3 = all 15 mastered), Spar (60 s, combo, best per belt), Belt Exam (paper replica: bank + blanks, symbol picks, confirm, pass rule, TEST READY badge presented by the Sensei), Scroll Review (belts with a mastered scroll, weighted by misses). A term is mastered after 3 right answers in any mode. Every belt is open.
- Saved: `setLevel('ancient-ninja-scrolls', 'all', belt 1–8, {stars, best})` for Train (best = first-try %); `store.gameData('ancient-ninja-scrolls')` = `{terms: {id: {c, m}}, spar: {rank: best}, exams: {rank: {best, passed}}, badges: {rank: true}}`. games.js `badge` makes the floor show "Test Ready: n belts".
- The Sensei is an original character (topknot, round glasses, long white beard, indigo robe): keep it friendly and not like any known character. Prompts and answers are Atkinson Hyperlegible (the bundled subset now includes Latin-1 accents).

## Button Masher (`button-masher/`)
- Fingering / slide-position trainer as a neon versus fighting game. NO microphone (never load `pitch.js` or `mic-gate.js`); loads `sfx.js`. No RANDOM NOTES / SCALES toggle: its 8 rivals ARE the modes (first 3, first 5, the four concert scales from `Scales.build(member, id).up`, then all four mixed), all under the plain key `button-masher`.
- Uses the saved instrument (`requireInstrument`) plus the member (`Modes.memberPick` when a group has several). Progress is keyed by MEMBER: `setLevel('button-masher', member.id, rival 1–8, {stars, best})` (`byMember: true` in games.js). Percussion (`bells`, `tonebells`) gets "Percussion: try Chime Heist!" instead of a diagram, in the game and on the floor (`noPlay`).
- `fingerings.js` is THE fingering table (`MASHER_FINGERINGS[memberId] = {diagram, notes: {'Bb4': [primary, alternates…]}}`): brass `'1-3'`, `'0'`, horn trigger `'T1-2'`, 4th valve `'4'`; trombone positions `[1, 6]`; woodwinds = the diagram's key ids separated by spaces (`'|'` ignored, `'1h'` = half-hole). A combo is right only when the pressed keys EXACTLY match one entry. To fix a fingering, edit that list (primary first); every note used by rivals 1–8 must be listed for every member (a missing note or unknown key id warns in the console). Its top comment lists the fingerings to verify against the 6th Grade Honor Band charts; keep that list current.
- `diagrams.js` draws each family (`flute`, `oboe`, `clarinet`, `sax`, `bassoon`, `trumpet`, `horn`, `euph`, `tuba`, `trombone`) as SVG with real tappable keys (pointerdown). Key ids are what fingerings.js uses: move keys freely, never rename ids. Half-hole keys (`half: true`) cycle open → half → closed.
- Rivals in `levels.js` (`MASHER_RIVALS`: name, look, colors, taunt, pool, notes, health, time, showName, hint); rules in `MASHER_RULES`. Stars: 3 = no mistakes (wrong or timeout), 2 = 1–2, 1 = won. Cartoon only: energy blasts, a "boing" counter, dizzy stars; no weapons or injury. The fighter and the rivals are original drawings in `game.js`.
- CHART view (rival screen only, never during a match) shows every note with its primary fingering drawn and alternates listed.

## Note Checker
- Modes FIRST 5 | B♭ | E♭ | F | A♭ | CHROMATIC (stored as 'five', 'Bb'…'Ab', 'full'). Scale modes show the scale up and down with its key signature; a held pitch lights the first dark place with that pitch, octave-exact, "11 of 15 notes".
- FIRST 5 NOTES: the original checker (letter names, any octave). CHROMATIC (FULL RANGE): the member's whole chromatic scale on wrapped staff rows (≥ 50 px per note so accidentals never touch), each note captioned.
- The octave rule: a note lights gold only when held in the octave written on the staff (exact sounding pitch via `sounds`). A same-letter note in another octave never counts; if the student replays a found note while its other octave is still missing, show "That's a D, but an octave lower. Try the higher one." Readings an octave outside the whole range are folded in by the pitch engine (mic error), so they do count.
- The note being heard gets a glowing outline; "Going down" shows the same pitches descending with flats (one set of found notes). `?demo` in full range: ↑/↓ pick a note, hold Space to play it, Shift+Space an octave low.

## Testing
- `python3 -m http.server` from the repo root, then open `http://localhost:8000/?demo`.
- Before finishing a change, verify with `?demo` that a level can be completed and that the arcade floor's HI-SCORE for that game updates (it shows only when an instrument is saved).
- `?demo` in SCALES (games) and the Note Checker's scale/chromatic modes: hold Space to play the note on the staff / the glowing note.
- Real-instrument testing is Mat's job. Ask him which instruments/notes misread rather than guessing at detector changes.

## Detector tuning (shared/pitch.js)
YIN with threshold 0.15, clarity ≥ 0.8, loudness gate from the sensitivity slider, ±0.65-semitone hysteresis, 110 ms release gap. Per-instrument search range comes from `range` in `instruments.js` (min × 0.78, max × 2.3). Change these carefully and note why in the commit message.
