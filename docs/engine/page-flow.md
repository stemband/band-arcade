# Page flow

1. `index.html`, the arcade: PRESS START → CHOOSE YOUR INSTRUMENT (pick mode, below) → THE ZONE LOBBY → a ZONE (its cabinet carousel), ALL GAMES or the FULL ARCADE → a game. All one page (arcade.js routes by the address; lobby.js draws the lobby and ALL GAMES), so the audio stays unlocked and the lobby ambience never restarts between views. Every view is a history entry (Back / the iPad back-swipe: game → zone → lobby):
   - LOBBY `index.html` (no hash): (during a SEASONAL EVENT: its banner + decorations first, see SEASONAL EVENTS in [seasons.md](seasons.md)) one neon sign per zone (games.js `ZONES`: color, name, tagline, small cabinet silhouettes `Arcade.cabSilhouetteSVG`, the zone's stars for the current instrument via `Arcade.gameStars`); 3 columns in landscape, 2 in portrait and on phones (7 zones today + the PRIZE COUNTER's sign last = 8 signs: a lone last sign stands centered, the same size, arcade.css `.zones` 6/4-column grid; a sign's cabinet silhouettes shrink to fit it; the prize sign is `.zsign.zs-prize` with no `data-zone`, see THE PRIZE COUNTER in [prize-counter.md](prize-counter.md)); each sign flickers on once per page load (two gentle dips, staggered, opacity only: measured 0 flashes over the WCAG 0.1 threshold) then hums (a slow glow). The arcade's name (`#arcadeName`, and `#psName` on PRESS START) and the Leaderboard title (the top bar's `#lbBtn` label, the screen's `#lbTitle`) are ALL CAPS by CSS only (`text-transform`, end of arcade.css; the text stays "Band Arcade"); no other text. On top: CONTINUE (the last game opened here: `store.gameData('floor').last`, set by arcade.js when a game opens) and ASSIGNED (`shared/featured.js`, `Arcade.featuredGame()`: `{game, note, until}`, off when null or after `until`). FLAT HTML/CSS ONLY: never three.js here; marquee pictures are `Arcade.Marquee.thumb(g)` still frames (drawn once per page and size from the marquee renderer, redrawn when a font or picture arrives).
   - A ZONE `#zone=<id>[&game=<id>]`: the carousel (◀ ▶, swipe, ←/→, lights, tap a side cabinet) with ONLY that zone's games, no repeats (1 game = no arrows; 2 games = a straight row, not a ring: the second stands right of the first, no wrap-around, the arrow at an end is `disabled`; 3+ = a ring as before), in the zone's `order` (below); the address follows the front cabinet (replaceState). ← LOBBY (`history.back()` when the lobby is under it, else to the lobby), the zone's name in the top bar (`--z` colors). START opens the game (below).
   - ALL GAMES `#all-games`: every floor game once (a game in two zones too), as a card: marquee thumb, name, zone tags, stars, 2P / ASSIGNED badges, and a "No instrument needed" tag (`.ni-tag`) on games.js `noInstrument: true` games. THE FILTER (`#niFilter`, a chip with `aria-pressed` above the cards): "No instrument needed" shows only those games (`#allCount` says how many), remembered for the browser session only (sessionStorage `bandarcade.noinst`). `noInstrument` = playable all the way through with NO LIVE INSTRUMENT (touch, taps, claps, on-screen keys): today Note Ninja, Keys to the City, Chime Heist, Rhythm Dojo, Ancient Ninja Scrolls, Button Masher, Dojo Duel, Blocktave (TOUCH mode) (check a new game's code before setting it: the mic for CLAPS only still counts; needing your instrument's notes anywhere does not). Tests: tests/arcade-exit.spec.js. Scrolls.
   - THE FULL ARCADE `#full-arcade[&game=<id>]` (the top bar's FULL ARCADE button, pink, next to ALL GAMES; hidden in the view itself): the SAME carousel as a zone (arcade.js keeps `current = 'zone'` with `zone = FULL`; `Arcade.Arcade.state().view` = 'full'), with every floor game once (`fullGames()`: zone by zone in `zoneList()` order, each zone's `zoneGames` order, a game in two zones only in its first; games in no zone last; no tools). A zone tag under each cabinet (3D: a small lit plate in front of its base, `opts.tag`/`setRing(…, tag)` in arcade3d.js, layer 1 = no reflection; 2D: `.cab-ztag`), the zone as a tag in the info, and the QUICK JUMP strip (`#jumpStrip`: `Marquee.thumb` buttons grouped by zone, `.jg` with the zone's color line + name; the front game's lit, `aria-current`, scrolled to the middle; a tap = `goTo(i)`, one quick spin; thumbnails filled in a few at a time after the cabinets). The lights are hidden there. Opens on `featuredGame()`, else `Lobby.lastGame()`, else the first game. Back from a game returns to it (sessionStorage `from.view = 'full'`); its Back button goes to where it was opened from.
   - THE TOP BAR (`.fbar`, every view): back, the title, LEADERBOARD (the trophy, when a scoreboard address is set: see THE LEADERBOARD in [leaderboard.md](leaderboard.md)), TUNE UP (`note-checker/index.html`: THE TOOLBOX, see TUNE UP (TOOLBOX) in [note-checker.md](../games/note-checker.md); games.js `tool: true`, NOT a cabinet; it stays in `A.GAMES` for its Select Player and sounds), ALL GAMES, FULL ARCADE, the AVATAR BADGE ([avatars.md](avatars.md): EDIT AVATAR / CHANGE INSTRUMENT = pick mode), sound.
   - OPENING A GAME (`openGame`): not suited to the saved instrument (games.js `fit`, `Arcade.gameFit(g, memberId)`) → the `#fitDlg` panel (tag + why + SWITCH INSTRUMENT = pick mode with `forGame`, which dims the unsuited tiles and opens the game after); a two-player game with its own Select Player (`players: 2` without `player`: Neon Face-Off) or no instrument saved → Select Player for that game; else `Sfx.playThenGo('select-<id>', '<id>/index.html')` with the saved instrument. Dimmed games stay visible everywhere with their `fit.tag` (2D `.slot.nofit`, 3D a `fade` factor on the cabinet, cards `.nofit`).
   - BACK FROM A GAME: its "← ARCADE" is `index.html#<game id>`; arcade.js reads sessionStorage `bandarcade.from` (`{view: 'zone'|'all'|'lobby', zone}`, written when the game opened) and shows that zone (or ALL GAMES, or the lobby) with the game in front, putting the lobby underneath in history. The Note Checker's comes back to the lobby.
   PRESS START (`#pressStart`, arcade.js): on the first visit of a browser session (sessionStorage `bandarcade.visit`), a full-screen attract screen (the neon sign, a blinking PRESS START, "TAP ANYWHERE" on touch screens / "PRESS ANY KEY"); it's a real, focused button; any tap/click/key dismisses it with a quick flash, and that same gesture unlocks the audio so the lobby ambience starts at once; then pick mode opens (CONTINUE AS is one tap). Later visits skip both (a device with no instrument gets pick mode once per page load). `?demo&nostart` skips PRESS START for tests.
   PRESS START (`#pressStart`, arcade.js): on the first floor visit of a browser session (sessionStorage `bandarcade.visit`), a full-screen attract screen (the neon sign, a blinking PRESS START, "TAP ANYWHERE" on touch screens / "PRESS ANY KEY"); it's a real, focused button; any tap/click/key dismisses it with a quick flash, and that same gesture unlocks the audio so the lobby ambience starts at once. Later visits skip it (the first tap anywhere still unlocks). `?demo&nostart` skips it for tests.
   A zone's cabinets are drawn in 3D (`arcade3d.js` + three.js, loaded together with `Arcade.need` the first time a zone opens; never in 2D) when WebGL works, else in 2D (`shared/cabinets.js`). `?flat` forces 2D; `?keep3d` (testing only) disables the automatic slow-device fallback; `?fps` shows the average frame time. `Arcade.Arcade.state()` = `{view, zone, game, ring, kind}` for tests.
2. SELECT PLAYER = `index.html?game=<id>` (`&players=2` for a two-player game: games.js `players: 2`; `Arcade.playerLink` builds it; `&need=pitched|noplay`), the `#selectView` view of the floor page. PICK MODE = `index.html?pick[=<game id>]` (+ the hash of the view under it) = `SelectView.open(null, {forGame, onDone})`: the instrument for the whole arcade, no game (the arcade's name as its sign, `.sp-view.pick`, select-music, no Player 2); confirming calls `onDone(memberId)` (arcade.js: `history.back()` to the view underneath, then opens `forGame` if it now fits) instead of going to a game. `select-player/player.js` = `Arcade.SelectView.open(game, {players, need})` / `close()` (everything it binds uses one AbortController, so closing removes it all), styles `select-player/style.css` (scoped under `.sp-view`), markup in index.html. arcade.js keeps the page in step with the address (`showView()`): START = `history.pushState` + open; the browser's Back/Forward (popstate) and "← ARCADE" close/open it; links inside the view to another game's Select Player stay on the page. While it's open `body.in-select` hides the floor and `Arcade.floorPaused` stops the 3D drawing. `select-player/index.html?game=<id>` still works: it redirects to `../index.html?game=<id>` with every flag. A fighting-game character select. The game's marquee (small), "CHOOSE YOUR INSTRUMENT" (the heading, `#spTitle`; `text-wrap: balance`, so narrow screens get two even lines; one line in landscape; the page title "Choose Your Instrument · …"; the view is still called Select Player in code and docs; every student-facing name of the screen says Choose Your Instrument). THE ANNOUNCER (player.js `announce`): the `choose-instrument` voice line plays as the view opens, 0.5 s in or when the last effect (the START sound, the coin) has ended (`Sfx.busy()`), whichever is later; only if a tap on this page already started the audio (`Sfx.started`; a page loaded straight onto the view stays quiet, never late); at most once a minute (sessionStorage `bandarcade.choose-at`, set when it plays, so coming back from a game after a minute plays it again); cancelled by a tap on a tile / CONTINUE / SELECT or an arrow/Enter/Space before it starts; held while a panel covers the view ("Create your player?", an UNLOCKED! card, the creator, the LOCKER); the heading swells once with it (`.sp-title.say`, none under reduced motion) and the music dips (`Sfx.duck`). The floor page `Sfx.prefer`s it at load (PRESS START), so it is decoded before the first play, "CONTINUE AS <instrument>" (with its portrait) when one is saved, a big preview + PLAYER CARD (name, key · clef, first five, stars on this device via `store.starsForPlayer`, the horn's "Starting notes: F–C / C–G" toggle = `store.setHornStart`, and a LOCKER button that opens THE LOCKER (see [avatars.md](avatars.md)): player items + this instrument's skins, live preview, locked ones as silhouettes with their requirement), and the 16 instrument tiles (`Arcade.PLAYERS` order; landscape ≥ 900 px: 6 columns × 3 rows with the last 4 centered (a 12-half-column grid, each tile spans 2); portrait and phones: 4 × 4; sizes from the grid + `clamp()`, never fixed px; names wrap, never cut off; in landscape the preview's portrait is sized from the screen height so the card and SELECT fit at 768 px tall; ↑/↓ go to the nearest tile in the row above/below on screen), tinted by family (woodwinds `--pink`, brass `--amber`, percussion `--cyan`). The big preview shows the student's AVATAR (Create Your Player) wearing the highlighted instrument's skins, with the instrument as a badge (`#pvInst`); the card names the player (`#cPlayer`, 1P tag) and has EDIT PLAYER (`#editBtn`: `Arcade.AvatarCreator.open`); CONTINUE AS shows the avatar; the LOCKER previews every item and skin ON the avatar. On a device's first visit Select Player asks "Create your player?" once (`AvatarBadge.offer` in avatar-badge.js, so it shows before the creator has loaded; `AvatarCreator.offer` is the same; `store.avatarOffered`; skippable: the random avatar stays), before the UNLOCKED! catch-up card (skins + player items). Page overlays go above the view (`body.in-select>.overlay`). Tap highlights (pulsing outline + 1P marker), tap again or SELECT confirms; arrows move, Enter selects. Confirm calls `Arcade.store.setPlayer(memberId)`, flashes "PLAYER 1 READY", then goes to the game. After the members migration it shows `store.pending` (the old group's tiles dashed + "Pick your exact instrument!", or the Colored Tone Bells notice). Two-player: after Player 1 (cyan 1P marker; "PLAYER 1 READY"), "PLAYER 2 — PRESS START": Player 1's tile keeps its 1P marker, Player 2's highlight is magenta with a 2P marker, a CPU tile joins the grid, the preview shows the GUEST avatar (`Avatar.guest()`; the card's buttons become EDIT GUEST + SURPRISE ME), "Same opponent" replaces Continue, and the choice is saved with `store.setOpponent(memberId | 'cpu')` (its own horn setting `opponentHornStart`), never replacing Player 1's instrument. A bad or missing `?game=` goes home.
3. Game pages: `Arcade.requireInstrument(GAME_ID)` returns the saved player's GROUP, or sends students with no saved instrument (member) to Select Player for that game. `Arcade.mountTopbar(inst, extraHTML, GAME_ID)`: "← ARCADE" goes home (turned to this game), the AVATAR BADGE (the avatar, its name, the member's `short` name) whose CHANGE INSTRUMENT opens Select Player for this game (a fixed-instrument game: the floor's pick mode, then the lobby).
- THE SAVED CHOICE IS AN INSTRUMENT MEMBER (`Arcade.store.player`: `'trumpet'`, `'oboe'`, `'horn'`…). Games never ask "Which instrument do you play?": the member IS the answer (`store.memberFor(group)` returns it, `Arcade.currentMember()` gives it). Behind the scenes it maps to its old player GROUP with **`Arcade.groupFor(memberId, {hornStart})`** (instruments.js; `store.instId` uses it), and every game keeps saving progress under the group id, so old stars never move. Always go member → group through that helper. Horn is one member in two groups (`hornF` / `hornC`), picked by `store.hornStart` ('F' default | 'C'). Colored Tone Bells is gone. The one-time `players-v1` migration in storage.js maps old saves (see README "Players and old saves").
- A one-instrument game sets `player: '<group id>'` (and `playerName`) in `games.js` (Chime Heist: `'bells'`); a game with no instrument sets `player: 'all'` (Ancient Ninja Scrolls; progress saved under inst id `'all'`, no label, no modes note). `Arcade.startLink(game, root)` then goes straight to the game (the floor's 2D and 3D START both use it), Select Player redirects there, the saved instrument is never changed, and the floor's hi-score reads that group. Such a game uses `Arcade.getInstrument(id)` instead of `requireInstrument`, and `mountTopbar(inst, extra, GAME_ID, {fixed: 'Bell Kit'})` shows a plain label instead of the instrument link. `noteModes: true` marks a note-reading game (the NOTES × ORDER picker; the floor shows its all-modes total).
- `players: 2` (Neon Face-Off) makes START and the chip open Select Player with `&players=2`.
- ZONES (games.js): `Arcade.ZONES` = the lobby's zones in order `{id (never rename: it's in addresses), name, color (a neon token name), tagline, order?}` (`order`: game ids the zone shows first, the first in front when it opens; Technique Lab starts on Showtime Malfunction, which suits every instrument); each game's `zones: [ids]` (more than one is fine; none = only in ALL GAMES); `auto: '<game flag>'` = the zone holds every floor game with that flag, in games.js order, never listed in `zones` (NO INSTRUMENT NEEDED, `auto: 'noInstrument'`, blue, right after the Band Ninja Dojo: a game flagged later joins by itself and stays in its own zones too; the FULL ARCADE skips auto zones so each cabinet stays once under its own zone; `zonesOf` (ALL GAMES' tags) leaves them out; `A.inZone(g, z)`; nothing in it is dimmed or asked to switch instrument: `gameFit(g, member, zone)`; tests/no-instrument-zone.spec.js); `fit: {only|not: [member ids], tag, why}` = which instruments it SUITS in the lobby (display only: the game's own page still uses `unpitched`/`noPlay`/`player`); `tool: true` = not a cabinet (the Note Checker). Helpers in ui.js: `Arcade.floorGames()` (games minus tools), `zoneById`, `zoneGames(id)`, `zoneList()` (zones with games), `zonesOf(g)`, `gameFit(g, memberId)` → `{ok, tag, why}`, `featuredGame()`, `gameStars(g)` (the current instrument's all-modes stars; a fixed-player game's own). Current fits: Scale Trainer not snare; Keys to the City every instrument (no instrument needed); Music Highway every instrument (the snare plays rhythms); Chime Heist every instrument (no `fit`: it always plays as the Bell Kit, `player: 'bells'`, and never changes the saved instrument, so it is never dimmed and never asks to switch; tests/chime-heist-fit.spec.js); Button Masher + Sustain Speedway not bells/snare ("Winds & brass only"); Ghost Notes, Note Storm, Note Ninja, Neon Face-Off, Lost Signal, Vanishing Ink not snare; the rest every instrument.
- `noPlay: {…, block: true}` (Sustain Speedway: bells + snare can't hold a long tone): `requireInstrument` sends those members to Select Player with `&need=noplay`, which dims their tiles (`.no-play`, via `Arcade.blockedBy(game, memberId)` in ui.js) and shows `noPlay.label` with links to `noPlay.games`; the floor shows the label as a link. Without `block`, `noPlay` only changes the floor's hi-score line.
- `byMember: true` (Button Masher, Neon Face-Off) saves progress under the MEMBER id (`trumpet`, `clarinet`…) of the saved player, and the floor's hi-score reads it. Every hi-score line names the player's member (`short`). `noPlay: {groups, members, label, game}` replaces the hi-score with a link to another game for instruments the game can't use (percussion → Chime Heist).

## Links and the instrument check

- Links: `Arcade.link(path)` keeps the query string. `Arcade.linkTo(path, {game})` keeps `?demo` but sets or drops `?game=` (use it for links between pages). `Arcade.playerLink(gameId, root)`, `Arcade.homeLink(gameId, root)`; `root` is `'../'` from a game folder (the default) or `''` from the site root.

- `Arcade.requireInstrument(gameId)`: the saved instrument, or redirect to Select Player (returns null).
