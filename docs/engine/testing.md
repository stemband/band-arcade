- WEBKIT DRAWS ON THE CPU IN MUSIC HIGHWAY'S AND SUSTAIN SPEEDWAY'S SPECS (helpers.js `CPU_DRAWING`: `test.use(CPU_DRAWING)` at the top of every `music-highway-*` and `speedway-*` spec; WebKit only, Chromium unchanged): Playwright's Linux WebKit (WPE) draws with Skia on the GPU, and on a CI machine (no GPU, software OpenGL) that path crashed the page in these canvas games now and then (the runner's kernel log: `WPEWebProcess … trap invalid opcode … in libWPEWebKit-2.0.so`, a `SkiaGPUWorker` segfault; Playwright: "Target crashed"). Measured on CI (those specs, 9 machines' worth of repeats): 14 crashes in ~200 runs on the GPU, 2 on the CPU (WebKit's compositor thread; CI's one retry covers them). Never an arcade bug (heap, DOM and canvases stay flat over a song or a race) and real Safari never takes that path. NOT for every spec: on the CPU, WebKit's WebGL (the Full Arcade's 3D floor) logs "glTexStorage2D: Texture is immutable" (the smoke test fails), and Blocktave's pages crash either way (still open). WHAT THE PAGE SAW (helpers.js `pageWatch(page)` before `goto`, then `explain(seen, state, fn)` around a wait): a failed wait adds the longest frame gap, frame and timer gaps over 1 s, hidden / pagehide, the game's own state, or "page gone: Target crashed"; Music Highway's full songs and slurs and Sustain Speedway's slur lap and podium races use it.
- WAITS ON A BUSY RUNNER: a CI runner can be several times slower than a laptop, and a loaded WebKit can starve a page's animation frames for seconds. A test never waits a fixed time for something a game does over its frames (wait for the thing itself, as Blocktave's Pearl and loot waits do), a `waitForFunction` for something that ends on a TIMER (a Blocktave card closing) re-checks on a timer (`polling: 100`), not on the page's frames (Playwright's default), and a demo answer hook never loops until done (Blocktave's note cards answer each note at most once). Blocktave's 20-seed chapter 1 tests print the page's longest frame gap and any hidden / pagehide when a seed fails.

## Keeping the tests fast

Every change adds tests, so the suite stays fast by rule (October 2026: a pull request's Tests hit the 40-minute limit; now QUICK CHECK answers in ~3 minutes and the whole run takes ~15).

- **THE TIME BUDGET: 60 s a test.** `tests/ci-summary.js` (run by ALL TESTS, and by each QUICK shard) fails the check for any test over 60 s that isn't tagged `@slow`, and the run summary lists the 10 slowest tests and every test that needed its retry.
- **TAGS** (Playwright's `{tag: '@quick'}` after the title): `@quick` = core, runs in QUICK CHECK (Chromium) and in WebKit's FULL shards; tag a new test `@quick` only if it is core (a page opens, a level starts, saving, the leaderboard's privacy) and fast. `@slow` = a test that IS about a long real-time run (a whole song, a Quest route, a race): it runs only in FULL. A game run gets `slow: true` in tests/games.js.
- **NO REAL SLEEPS.** Never `waitForTimeout` to "let things settle": wait for a state (`Arcade.*.state()`, `waitForFunction`, `expect.poll`), an element or an event. A wait for something that ends on a timer polls on a timer (`polling: 100`).
- **USE THE TEST CLOCK** where a test waits for time to pass: `page.clock` (install before `goto`; `runFor`/`fastForward`), or the game's own: Blocktave's `demo.step(seconds, each)` runs the world in fixed 60 fps steps at once (movement, falling drops, pickups: the result never depends on the machine's frame rate). Never count frames: a busy WebKit test machine draws ~6 a second (check the game's own numbers, e.g. Neon Face-Off's `look.trailMax`).
- **SPLIT, DON'T LOOP.** A test that repeats the same check at every screen size, seed or block type is one test per size/part (`for (…) test(\`… (${name})\`, …)`): they run side by side and a crash costs one short retry.
- **SHARED STATE:** none. Every test gets a fresh browser context (its own storage); seed storage with `prepare(page, {store})`.
- **GALLERY:** screenshots for Mat's review only with `GALLERY=1`.
- **WEBKIT ON CI** has no sound card (its audio clock doesn't keep time: Music Highway and Rhythm Dojo play with SOUND OFF there; Blocktave's 5 audio-clock tests run in Chromium only) and no GPU (its WebGL logs `glTexStorage2D: Texture is immutable`, ignored by helpers.js; `ResizeObserver loop` notices are ignored too).
