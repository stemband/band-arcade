# Testing

- **Every PR must pass the tests.** New games must pass the smoke and game-run tests; add a tests/games.js entry if the game needs special steps.
- THE AUTOMATIC TESTS (`tests/`, README there; `.github/workflows/tests.yml` runs them on every pull request and push to main, Chromium + WebKit): SMOKE (`smoke.spec.js`: every page in `pages.js` at iPad landscape/portrait and Chromebook sizes: no JS/console error, no missing local file (except the optional files the site probes for: `OPTIONAL` in helpers.js), no outside host, no visible button off the screen sideways), GAME RUNS (`game-runs.spec.js` + `games.js`: every game in shared/games.js from ?demo Level 1 to its results with stars saved, Endless cards to GAME OVER; a game needing other steps gets a STEPS entry), PITCH (`pitch.spec.js`, Chromium: synthesized clarinet/flute/sax/trumpet/tuba tones through `Pitch._analyse`, octave-exact), NETWORK (`network.spec.js`: the leaderboard mocked, only the allowed fields, nothing in ?demo), SAVE (`save.spec.js`: the Arcade Backup Code round trip), AVATAR ITEMS (`avatar-items.spec.js`: old Quest codes v1–v3 read exactly as before, a v4 round trip, the Tumblers and the Grandmaster's Aura) SHOWTIME SNARE (`showtime-snare.spec.js`: every snare job with `Onsets.fake(time, level)`, fairness at every showtime) TUNE UP (`tuneup.spec.js`: the tabs and the mic per tab, the balloon's height/words/arrows, written vs concert names, HOLD IT, the tips, HEAR THE NOTE with the mic paused + TARGET mode, the snare's tab, the metronome's schedule/accents/6-8/subdivisions/tap/tempo words/silent mode/the bop on the audible beat/reduced motion/hidden tab, the Tempo Ladder on downbeats + HOLD + STEP BACK + the goal, the two items) SOUNDS (`sounds.spec.js`: every file in shared/sounds/ decodes in the browser; one the compressor processed is within 30 ms of its upload's length in `fixtures/sound-durations.json` (.m4a 0.1 s; the open-source Chromium has no AAC, so .m4a is decoded in WebKit) and a music loop's first/last 20 ms still sound; plus tests.yml's `sounds` job: `tools/compress-sounds.py --check` and `--verify` with ffmpeg, see [sound.md](sound.md)) and RHYTHM DOJO (`rhythm-dojo.spec.js`: every Counting Board example, synthesized claps found to the millisecond, the game's own clicks looped back into the clap detector never counting, judging/rests/holds/feedback colors, the timing check, HEAR IT and pause). Run them: `cd tests && npm ci && npx playwright install chromium webkit && npx playwright test`.
- THE PUBLISHED COPY: `tests.yml` runs the whole suite twice in each browser: on the repository's files (`tests (chromium)`, `tests (webkit)`) and on the copy the Pages deploy publishes (`tests on the published copy (…)`): `node deploy.js <folder> testbuild` (tests/deploy.js: copy the site, then stamp → minify → fingerprints, the same steps as pages.yml) and `ARCADE_SITE=<folder>` (playwright.config.js serves that folder; the tests still read the repository's files for their expectations). Both must pass: it is what catches anything minification breaks. Locally: `node deploy.js /tmp/site testbuild && ARCADE_SITE=/tmp/site npx playwright test`. The app tests (`app.spec.js`) always deploy their two versions this way, and check that an update downloads only the files whose published bytes changed. See [version-and-app.md](version-and-app.md) "THE DEPLOY PIPELINE".
- PAGE WEIGHT (`perf.spec.js`, Chromium): on a published copy the lobby's JavaScript at load stays under `LOBBY_JS_BUDGET` (the measured size + 10 %; the failure names the biggest files) and the on-demand scripts aren't loaded at startup (skipped on the repository's 'dev' copy). `PERF=1` also MEASURES the lobby and Music Highway on a slow school device (4× CPU, Fast 3G, empty cache): script requests, JS decoded / gzipped, script time, ready time (lobby.js's `performance.mark('lobby-ready')`). Compare two copies with `ARCADE_SITE=<folder> PERF=1 npx playwright test perf --project=chromium --workers=1`.
- `python3 -m http.server` from the repo root, then open `http://localhost:8000/?demo`.
- Before finishing a change, verify with `?demo` that a level can be completed and that the arcade floor's HI-SCORE for that game updates (it shows only when an instrument is saved).
- `?demo` in the mic games (any NOTES pool) and the Note Checker's scale/chromatic modes: hold Space to play the note on the staff / the glowing note.
- Real-instrument testing is Mat's job. Ask him which instruments/notes misread rather than guessing at detector changes.

## Demo mode

- `Arcade.DEMO` is true with `?demo`. Keys 1–5 fake the five notes, and games should unlock all levels.

## Docs
- DOCS (`docs.spec.js`): CLAUDE.md ≤ 25 KB, a `docs/games/<id>.md` for every game in `shared/games.js`, every file in `docs/engine/` and `docs/games/` listed in CLAUDE.md's index, no broken links between the doc files. A new game or system gets its doc file and an index row in the same change.
