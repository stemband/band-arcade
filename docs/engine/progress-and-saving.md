# Progress and saving

- `Arcade.store`: `exportAll()`/`importAll(obj)` (the whole device, for shared/backup.js), `allStars('*')` (every star on the device), `ownedItems`/`ownItem(key)` + `itemsSeen`/`markItemsSeen(keys)` (avatar items), `avatar`/`setAvatar(av)`, `guestAvatar`/`setGuestAvatar(av)`, `avatarOffered`/`setAvatarOffered()` (Create Your Player), `player`/`setPlayer(memberId)`, `instId` (the player's group), `hornStart`/`setHornStart('F'|'C')`, `pending`, `opponent`/`setOpponent(memberId | 'cpu')` + `opponentHornStart`/`setOpponentHornStart` (Player 2 in two-player games), **`allStars(instrument, gameId?)`** (THE star total: every progress key (all NOTES × ORDER combinations, every game's modes) for an instrument (a member id, or a player id like `'bells'`), for one game or all games; use it wherever a total is shown or checked: the floor's hi-score, the player card, future unlocks; `starsForPlayer(m)` = `allStars(m)`), `noteMode(gameId)`/`setNoteMode(gameId, {notes, order})` (reads choices saved by the old picker too), `sens`, `sfx`, `ambience`, `checkerMode` ('five'|'Bb'|'Eb'|'F'|'Ab'|'full'|'art'), `memberFor(groupId)`/`setMember(groupId, id)`, `level(game, inst, lvl)`, `setLevel(game, inst, lvl, {stars, best})`, `totalStars(game, inst)`, `hasProgress(game, inst)`, `gameData(gameId)` + `saveGameData(gameId)` (a game's own extra records, kept out of `games`), one-time moves in `migrate()` flagged in `data.migrated`, `dayKey(date?)` ('YYYY-MM-DD' in the device's time, default `today()`, so `?demo&today=` counts), `reload()` (read the saved data again: ONLY the floor page uses it, through shared/practice.js, on `storage` / a Back-button `pageshow` / the tab showing again, because nothing there keeps saved objects between calls; a game page must never call it).
- THE DAILY ACTIVITY LOG (`store.activity`, `activityOn(day)`; shape in [seasons.md](seasons.md)): `f: {gameId: 1}` = a round of that game FINISHED that day, set by `store.noteFinished(gameId)` (saved the first time a day; `g` and `p` stay as they were, so seasonal events count nothing new): `UI.results.show` calls it for its `gameId` (else `A.pageGame`), which covers every game on the shared results screen and every Endless GAME OVER; the games that finish without it call it themselves: Dojo Duel (a match's end: `victory()`, its results are `UI.results.render`), Arcade Quest (a battle won or lost: battle.js `run()` before it leaves), Blocktave (a night survived: `dawn()`; a challenge card passed: `openCard`'s onDone with `ok`). Neon Face-Off's matches use `UI.results.show`. Read by TODAY'S PRACTICE ([page-flow.md](page-flow.md)). Progress shape: `games[gameKey][instId][level] = {stars, best}`. Note-reading games use the PROGRESS KEYS table in [notes-and-scales.md](notes-and-scales.md). The home page's hi-score shows `allStars` for the game ("all modes") and "Modes played: n of 12" (games.js `noteModes: true`).

## Save codes (Quest codes + the Arcade Backup Code)

- SAVE CODES (`shared/backup.js`, loaded by the floor, Select Player and Arcade Quest): alphabet `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (no 0/O/1/I), spaces/dashes/lower case ignored. QUEST CODE v1 = 25 chars (5 × 5), 125 bits: version 4 · level 6 · xp 9 · tokens 11 · `QUEST_V1.items` × 3 · `roster` × 1 · `flags` × 1 · `ghosts` (room:key) × 1 · jukebox 3 · stars converted 11 · pad to 110 · CRC-32 check 15. QUEST CODE v2 = 40 chars (8 × 5): the v1 fields (106 bits, version 2) · `QUEST_V2.charms` owned × 1 (8 places) · equipped 3 + 3 · `QUEST_V2.cosmetics` unlocked × 1 · worn × 1 · pad to 185 · check 15; loading one gives the charms, makes the listed avatar items owned (`ownItem`) and puts the worn ones back on. Those lists ARE the format: never reorder/remove, only append within the padding; a new episode adds a version and keeps reading v1 and v2. QUEST CODE v3 = 45 chars (9 × 5): the v2 layout (version 3) with `QUEST_V3.cosmetics` (= V2's 30 + 13 newer Token Booth items) · pad to 210 · check 15. QUEST CODE v4 = 60 chars (12 × 5): the same layout (version 4) with `QUEST_V4.cosmetics` (= V3's list + the Tumblers) · pad to 285 · check 15 (FROZEN). QUEST CODE v5 (what `Q.save.code()` makes now; THE SHARED WALLET can pass 2047) = 65 chars (13 × 5): version 4 · level 6 · xp 9 · TOKENS 16 · items · roster · flags · ghosts · jukebox 3 · stars converted 16 (= 116 bits) · charms 8 + 3 + 3 · `QUEST_V5.cosmetics` (= V4's list; new {shop} items go at its END; room for 90) unlocked × 1 · worn × 1 · pad to 310 · check 15 (`questEncode(save, {version: 4})` still makes the old layout, for tests). Each version reads with its OWN frozen list and field sizes, so v1–v5 all load and an old code decodes exactly as before (tests/avatar-items.spec.js + tests/fixtures/quest-codes.json: v1–v4; v5: tests/prize-counter.spec.js). Loading a code puts its tokens and `convertedLeft` in the wallet through `Arcade.Tokens.restore`. `Q.save.code()` / `Q.save.fromCode(code)` (engine/save.js); shown at every Save Jukebox (`Q.talk.showCode`; the Foyer's and the Attic's, both in `QUEST_V1.jukeboxes`; the jukebox's menu: SAVE HERE · YOUR BAND · NOT NOW), ENTER SAVE CODE on the title (`Q.talk.enterCode`, asks before replacing). `convertedLeft` = a code's turned-in stars, spread over this device's star sources the next time either counter counts them (`Tokens.starSources`). ARCADE BACKUP (everything: `A.store.exportAll()`/`importAll()` in storage.js) = `BKP` + format `A` + `Z` (CompressionStream deflate-raw) or `R` + base-32 bytes + 7 chars of CRC-32; `A.Backup.open()` (the BACKUP / RESTORE panel: make + COPY, the short Quest code, paste + RESTORE → "This will replace this device's progress. Continue?" → reload), `A.Backup.button(el, cls)` (the Settings panel's "Your progress" group on the floor, Select Player's `#backupBtn` under the card); also opened from Arcade Quest's ENTER SAVE CODE (Backup) and the Save Jukebox's code panel (Backup), and the app's first-launch BRING YOUR PROGRESS (`.app-backup`). The panel is a `UI.layer` (z 80, on top of whatever opened it; focus on MAKE MY BACKUP CODE, Tab stays inside, Esc closes, focus back to the opener; its RESTORE confirmation above it); the overlay scrolls, and on an iPad the on-screen keyboard (visualViewport) pads the panel and scrolls the focused box into view. A typo = `A.Backup.BAD` ("That code doesn't look right. Check each letter."). `A.Backup.open({make: true})` makes the code at once (focus on COPY: the lobby's SAVE NOW). On top: "Last saved: Oct 3" / "Never saved on this device" (`gameData('backup-nudge').savedAt`, the year added when it isn't this year). Under the code: COPY, SAVE TO FILE and "Where to keep it: Paste it into a Google Doc or an email to yourself on your school account." SAVE TO FILE = `band-arcade-backup-YYYY-MM-DD.txt` (`A.Backup.fileText(code)`: the code in lines of 10 groups, the date, the instrument, the 3 restore steps), made in the browser with a Blob (no network); on an iPad (`A.App.ios`) the share sheet when `navigator.canShare({files})` says yes (closing the sheet saves nothing), otherwise a download. RESTORE: "Open a backup file" (a hidden file input, .txt) finds the code in the file (`A.Backup.codeInFile(text)`: from `BKP` to the next empty line, else the whole text), puts it in the box and runs exactly the same check as a typed code.

## SAVE YOUR PROGRESS (the lobby's nudge: `shared/backup-nudge.js`)

- WHY: everything a student earns lives only in ONE browser's storage. Safari on iPad can delete a website's saved data after about 7 days without a visit, unless the arcade is installed to the Home Screen (a long school break is exactly when that happens); district Chromebooks get powerwashed or swapped. A Backup Code is the only way back, and before this nothing ever reminded students it exists.
- WHERE: a slim banner under the lobby cards (`#saveNudge`, between `#lobbyCards` and `#zones` in index.html; styles `.bn-*` in arcade.css), never a popup. Only on the lobby: never in a game (the file only draws on a page with `#lobby`), on PRESS START, in pick mode / Choose Your Instrument, or while a panel is open (any `body > .overlay`, a kit panel, a `UI.layer`: the UNLOCKED! card, Settings, the Prize Counter…); then it waits and looks again every second. `lobby.js` calls `BackupNudge.refresh()` every time the lobby is drawn; also when the tab shows again and when another tab saves.
- THE SETTINGS (the commented `NUDGE` block at the top of backup-nudge.js, Mat edits it; **update `breaks` each August**): `stars` 25, `days` 14, `firstAfterStars` 10, `snoozeDays` 4, `maxPerWeek` 1, `breaks` (the LAST school day before each long break, 'YYYY-MM-DD').
- WHEN (`BackupNudge.status(day?)` → `{kind, show, why, newStars, days, total, savedAt}`): only with an instrument saved and UNSAVED PROGRESS (stars since the last backup = `allStars('*')` − `starsAtSave`, or days in the activity log with stars (`s`) after `savedAt`), and one of: new stars ≥ `stars` or progress days ≥ `days` (kind `stars`: "Save your progress! You've earned 32 ★ since your last backup.", or "…You've played on 14 days since your last backup." when the stars didn't grow); never saved and ≥ `firstAfterStars` stars (kind `new`: "Keep your stars safe: make a Backup Code."); today or the next school day (Monday–Friday) is in `breaks` (kind `break`, any unsaved progress, first: "Break is coming! Save your progress so nothing gets lost."). NEVER while snoozed (`snoozeUntil`), when it already showed on `maxPerWeek` other days this week (weeks start Monday; the day it showed it may show again until saved or "Not now"; a BREAK nudge ignores the weekly limit, so the day before and the break day both get it), or with nothing new.
- THE BANNER: a drawn floppy disk (inline SVG, `currentColor`), the line, SAVE NOW (`btn-primary`: `A.Backup.open({make: true})`, through `A.need(['shared/backup.js'])` when the on-demand loader exists, so backup-nudge.js never needs backup.js before the tap) and Not now (`snoozeUntil` = today + `snoozeDays`; the focus goes to the first zone sign). The iPad tip: on an iPad that is NOT the installed app (`A.App.ios && !A.App.standalone`), the `new` and `break` nudges add "Tip: Add Band Arcade to your Home Screen so iPad keeps your progress." + SHOW ME HOW (`A.App.install()`: the Add to Home Screen steps). `role="status"`, buttons 48 px, reachable by Tab, never takes the focus. Fades in once per page load (`.bn-in`, opacity only; none under reduced motion or the Motion switch). No sound but the normal tap. Gold border for a break, cyan otherwise. Friendly words only: no countdowns, nothing scary.
- WHAT COUNTS AS SAVED (`BackupNudge.saved()`, the ONE place every way of saving reports to): the panel's COPY when the copy worked, SAVE TO FILE (a download, or a finished share), and a RESTORED Backup Code (`saved({restored: true})`: the panel's RESTORE, typed or from a file, and the app's BRING YOUR PROGRESS) = `savedAt` today and `starsAtSave` = the star total after the restore. Opening the panel, or making the code without copying it, is NOT saved. After saving: the banner goes and a toast says "Saved! Keep that code somewhere safe 💾" (not after a restore: the page reloads). backup-nudge.js is loaded wherever backup.js is (the floor page and Arcade Quest), so saving at a Save Jukebox's Backup counts too.
- SAVED in `gameData('backup-nudge')` = `{savedAt: 'YYYY-MM-DD', starsAtSave, snoozeUntil, shown: ['YYYY-MM-DD'…] (the last 10 days it was really on screen)}`. It travels in the Backup Code like every gameData (and a restore overwrites `savedAt`/`starsAtSave`). Nothing is sent anywhere.
- TESTS: tests/backup-nudge.spec.js (`?demo&nostart&today=`).
