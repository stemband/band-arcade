# The leaderboard

- THE LEADERBOARD (`shared/leaderboard-config.js` + `shared/leaderboard.js`, loaded after seasons.js on every page that saves progress; `leaderboard-screen.js` on the floor, the top bar's trophy `#lbBtn` (in the center group; on a phone too narrow for it, the avatar badge's menu: THE TOP BAR in [page-flow.md](page-flow.md)); `.lb-*` in arcade.css; README "Leaderboard & privacy"): Mat's Apps Script scoreboard. API: GET `?action=status` → `{ok, enabled}`; GET `?action=board&grade=6|7|8` → `{ok, enabled, grade, week, updated, boards: {stars, improved, streak, endless: {<gameId>: [...]}}, champions}` (`champions`: WEEKLY CHAMPIONS below), GET `?action=champions&grade=…`, entries `{id (6 chars), name: [t, a, n], value}`; POST (Content-Type text/plain: no CORS preflight) `{pid, grade, name, game, type, value, level}`. fetch with `credentials: 'omit'`, redirects followed (Apps Script → googleusercontent), SIMPLE CORS REQUESTS ONLY (no preflight: Apps Script can't answer one): GET with no headers, POST with only `Content-Type: text/plain`, and NO `cache` option (WebKit has turned a non-default cache mode into Cache-Control/Pragma request headers); never blocks a game. A COLD SCRIPT can take 10–20 s: `Leaderboard.TIMEOUTS` = {read: 25000, send: 20000} ms, a board read that times out is tried ONCE more; WARM-UP `Leaderboard.warm()` = one quiet `?action=status` (result ignored, never in ?demo, at most once in 10 minutes: sessionStorage `bandarcade.lb-warm`), called by arcade.js when the floor opens, when the lobby shows and when the page comes back on screen on the lobby. THE LAST GOOD BOARD of each grade is kept in localStorage `bandarcade.lb-last` (not progress, not in the Backup Code): a failed read returns it `{ok, data, stale: true, at, why}`. `Leaderboard.lastRequest()` = `{ok, why ('timeout after 25 s' | 'offline' | 'HTTP 500' | 'not JSON' | 'network error (CORS or blocked)'), ms, tries, at, action}` (warm-ups don't count). EVENTS (storage.js calls them): `stars` = a level's best stars INCREASE (setLevel), `endless` = the score at game over when it beats this device's best this week for that game (addEndless), `play` = once a day PER GAME: the first time each game is started that day (noteActivity with `play`; `plays` = `{day: 'YYYY-MM-DD', games: [ids]}`, started over when the day changes; storage.js migration `lb-plays-per-game` turned the old `day` field into it). The streak board is unaffected (any event on a day counts). A QUEUE on the device (≤ 250, oldest dropped), sent one at a time and PACED (at most `Leaderboard.PER_HOUR` 100 sends in any hour on this device, localStorage `bandarcade.lb-sent`, not progress; the server allows 150 per player), so a big catch-up goes out over the queue's normal retries, a failed/offline one retried (online, visible again, every 60 s); a refused one is dropped. Saved in `gameData('leaderboard')` (in the Arcade Backup Code): `{pid (24 × [a-z0-9]), grade, on (default true), queue, plays, week, weekStars, endless, id (the device's 6-char id when the scoreboard returns one), awards, champCheckedWeek, champLast (WEEKLY CHAMPIONS below)}`. THE SCREEN: the header reads 🏆 LEADERBOARD 🏆 (a trophy each side, the right one mirrored, both `aria-hidden`: the heading reads "Leaderboard"), centered on the whole panel by a 3-column header (`.lb-head`: an empty 48 px column, the title, ✕ 48 px), so ✕ at the right edge never pushes it off center (tests/top-bar.spec.js: within 4 px); first open asks the grade (6/7/8, changeable in MY SETTINGS with the switch "Show me on the leaderboard" + "Only your avatar name and scores are shared. ## PRIVACY: the only two things that send data
Only two files ever send anything off a device, and both only to `Arcade.LEADERBOARD_URL`:
1. `shared/leaderboard.js` (above): `{pid, grade, name numbers, game, type, value, level}`.
2. `shared/bug-report.js` (below): `{type: 'error', game, message, where, browser, version, count}`, nothing about the student.

Never add a field to either without Mr. Graham's OK.

## ANONYMOUS BUG REPORTS (`shared/bug-report.js`, `Arcade.BugReport`)
When something breaks on a student's device, a small anonymous note goes to Mat's scoreboard (Leaderboard.gs v5), which writes it to the Sheet's **Errors** tab.
- LOADED ON EVERY PAGE by `shared/version.js` (checkVersion's tags, in the `<head>`): `leaderboard-config.js`, `teacher-settings.js`, then `bug-report.js`, before the UI kit and every page script, so it hears every error after it. Not on a page shown inside other sites (`<meta name="arcade-app" content="off">`: the avatar card). Pages that list `leaderboard-config.js` / `teacher-settings.js` themselves load them a second time (harmless: the same values).
- WHAT IT HEARS: `error` events on `window` (script errors only: a failed picture or sound never reaches it) and `unhandledrejection`. Only errors from the arcade's own files (`Arcade.ROOT`): never another site's script, a browser extension, or bug-report.js itself. Ignored noise: "ResizeObserver loop…", "Script error." with no file, an error with no file of ours.
- WHAT A REPORT IS (one POST per report, `Content-Type: text/plain`, JSON, a CORS simple request like the leaderboard's): `{type: 'error', game, message, where, browser, version, count}`. `game` = the page's folder ('blocktave'; the floor = 'arcade'); `message` = the error's message only (no stack), web addresses replaced with "[address]", ≤ 200 characters; `where` = the file NAME + line ("game.js:812", found from the event or the first of our files in the stack; never an address or query string); `browser` = family + major version ("Safari 17", "Chrome 128"); `version` = `Arcade.VERSION`; `count` = times since the last send. NEVER the player id, grade, avatar name, instrument, stars, anything typed, page addresses, localStorage or the stack.
- ON THE DEVICE: the same message + where is one report with a count; at most `MAX_KINDS` (5) different reports a page load; the first send 2 s after the first error (a burst = one report), then at most one send every `SEND_GAP` (30 s); `pagehide` sends what waits (`navigator.sendBeacon` with a text/plain Blob, else `fetch` keepalive). Nothing stored; a failed send is dropped.
- OFF: `?demo`, the test runner (`navigator.webdriver`), no scoreboard address, `VERSION` 'dev' (the repository, local files, `python3 -m http.server`), or teacher-settings.js `BUG_REPORTS: false`. It does NOT depend on the student's "Show me on the leaderboard" switch or a grade, because it carries nothing about the student.
- NEVER BREAKS ANYTHING: every part is wrapped in try/catch; a failure inside it is silent.
- THE SCOREBOARD (Leaderboard.gs v5, Mat's): keeps only those fields (cleaned, message ≤ 200, addresses → "[address]"), drops anything else; the same error + game + where + browser + version on the same day = one row with a Count.
