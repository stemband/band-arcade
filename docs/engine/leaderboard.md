# The leaderboard

- THE LEADERBOARD (`shared/leaderboard-config.js` + `shared/leaderboard.js`, loaded after seasons.js on every page that saves progress; `leaderboard-screen.js` on the floor, the top bar's trophy `#lbBtn`; `.lb-*` in arcade.css; README "Leaderboard & privacy"): Mat's Apps Script scoreboard. API: GET `?action=status` → `{ok, enabled}`; GET `?action=board&grade=6|7|8` → `{ok, enabled, grade, week, updated, boards: {stars, improved, streak, endless: {<gameId>: [...]}}, champions}` (`champions`: WEEKLY CHAMPIONS below), GET `?action=champions&grade=…`, entries `{id (6 chars), name: [t, a, n], value}`; POST (Content-Type text/plain: no CORS preflight) `{pid, grade, name, game, type, value, level}`. fetch with `credentials: 'omit'`, redirects followed (Apps Script → googleusercontent), SIMPLE CORS REQUESTS ONLY (no preflight: Apps Script can't answer one): GET with no headers, POST with only `Content-Type: text/plain`, and NO `cache` option (WebKit has turned a non-default cache mode into Cache-Control/Pragma request headers); never blocks a game. A COLD SCRIPT can take 10–20 s: `Leaderboard.TIMEOUTS` = {read: 25000, send: 20000} ms, a board read that times out is tried ONCE more; WARM-UP `Leaderboard.warm()` = one quiet `?action=status` (result ignored, never in ?demo, at most once in 10 minutes: sessionStorage `bandarcade.lb-warm`), called by arcade.js when the floor opens, when the lobby shows and when the page comes back on screen on the lobby. THE LAST GOOD BOARD of each grade is kept in localStorage `bandarcade.lb-last` (not progress, not in the Backup Code): a failed read returns it `{ok, data, stale: true, at, why}`. `Leaderboard.lastRequest()` = `{ok, why ('timeout after 25 s' | 'offline' | 'HTTP 500' | 'not JSON' | 'network error (CORS or blocked)'), ms, tries, at, action}` (warm-ups don't count). EVENTS (storage.js calls them): `stars` = a level's best stars INCREASE (setLevel), `endless` = the score at game over when it beats this device's best this week for that game (addEndless), `play` = once a day PER GAME: the first time each game is started that day (noteActivity with `play`; `plays` = `{day: 'YYYY-MM-DD', games: [ids]}`, started over when the day changes; storage.js migration `lb-plays-per-game` turned the old `day` field into it). The streak board is unaffected (any event on a day counts). A QUEUE on the device (≤ 50, oldest dropped), sent one at a time, a failed/offline one retried (online, visible again, every 60 s); a refused one is dropped. Saved in `gameData('leaderboard')` (in the Arcade Backup Code): `{pid (24 × [a-z0-9]), grade, on (default true), queue, plays, week, weekStars, endless, id (the device's 6-char id when the scoreboard returns one), awards, champCheckedWeek, champLast (WEEKLY CHAMPIONS below)}`. THE SCREEN: first open asks the grade (6/7/8, changeable in MY SETTINGS with the switch "Show me on the leaderboard" + "Only your avatar name and scores are shared. Never your real name."); grade switch (other grades viewable); tabs STARS THIS WEEK / MOST IMPROVED / PRACTICE STREAK / ENDLESS (+ game picker, `Leaderboard.ENDLESS_GAMES`); top 10 with #1–3 gold/silver/bronze, the device's own entry highlighted (`isMe`), else "You: 12 stars this week. Keep going!" from this device's numbers; "Resets every Monday · Updated a minute ago"; boards cached 60 s (sessionStorage); while a board loads: "Loading the leaderboard…" (`.ui-msg.loading` = the UI kit's spinner, `.lb-loading`), never the break message; a failed read with a saved board = that board + "Couldn't refresh — showing the board from 2 hours ago" (`.lb-stale`); nothing saved (or disabled) = "Leaderboard is taking a break. Your progress is still saved!". `?teacher` shows each entry's 6-character id (Mat blocks a player in the Sheet's Blocked tab) and under the board how the last request went (`.lb-diag`: "Last request failed: timeout after 25 s (took 50.1 s, tried twice)."). WEEKLY CHAMPIONS (the block of that name in shared/leaderboard.js + `champion-lobby.js` on the floor + the screen's strip; Mat's Leaderboard.gs v4 works out the champions and lists them on the Sheet's **Champions** tab): GET `?action=champions&grade=7` → `{ok, enabled, grade, champions: {week: 'YYYY-MM-DD' (last week's Monday), stars: [entry…], improved: [...], streak: [...], endless: {gameId: [...]}}}`, entry = `{id, name: [t, a, n], value}` like a board row; everyone tied for 1st is listed (a tie is a full championship, no "tied" wording); an empty list = nobody reached the minimum. The board read carries the same `champions` object (the screen uses that, no extra request). PRIVACY: the champions check is a GET with only action + grade; the device matches its own id locally. No new data is sent. It runs only when `canSend()` (an address, the switch on, a grade, not ?demo); `Leaderboard.champions(grade)` = the same read rules as `board()` (simple GET, the timeouts, cached 60 s, the last good answer kept; the check's own read is quiet, so `lastRequest()` stays the boards'). THE CHECK `Leaderboard.checkChampion({force})`: the lobby calls it (champion-lobby.js, after first paint when idle; never blocks anything) only while the lobby is on screen; once a week (`champCheckedWeek` = last week's Monday, set after a good answer whose `week` is last week); a failed/offline check tries again at a later lobby showing, at most every 10 minutes (sessionStorage `bandarcade.lb-champ`); it counts as the warm-up (sets `bandarcade.lb-warm`). This device's id = `gameData('leaderboard').id`, else `pid.slice(0, 6)` (`Leaderboard.myId()`); it is looked for in every list (stars, improved, streak, each endless game) of the grade saved now (a grade changed during the week may simply not match). Each match = an award. Only LAST week is ever offered: a student who opens the arcade two weeks later quietly misses that week. SAVED in `gameData('leaderboard')` (Backup Code: a restored device never pays twice): `awards: {'YYYY-MM-DD': {stars | improved | streak | 'endless:<gameId>': {value, claimed}}}` (52 weeks kept), `champCheckedWeek`, `champLast` ({ok, why, at, found}, for ?teacher). THE REWARDS (Mat edits, top of the block): `CHAMPION_REWARDS = {stars: 100, improved: 75, streak: 75, endless: 50 (tokens per 1st place), plate: 1 (championships for the CHAMPION name plate), trophyGold: 5 (for the GOLD TROPHY back item)}`. CLAIM (`Leaderboard.claim()`): the record is read fresh (`store.reload()`) and written `claimed` FIRST, then `Tokens.add` once per award (so a reload or a second tab never pays twice; `arcade:tokens` redraws the Prize Counter sign), then `grantItems()` writes the items earned so far into `ownedItems` (`plate:champion`, `back:goldtrophy`; never sold: [avatars.md](avatars.md)); a good check grants them too (if Mat lowers a number). THE LOBBY CARD (champion-lobby.js, `Arcade.ChampionLobby.render/show/state`): an unclaimed award shows the CHAMPION card (overlay `.ch-ov`, a kit panel, `UI.layer` trap, Esc = CLAIM) when the lobby is idle: never over PRESS START, pick mode (body.in-select), the Create Your Player offer, the leaderboard screen, or any other open panel/overlay (it checks again every second; the leaderboard screen's close shows it at once). It has the avatar in its VICTORY pose (`AvatarFight.stillHTML`, else the bust) with a 🏆 in a spotlight, "🏆 CHAMPION!", one line per award ("You finished 1st in 7th grade for MOST STARS (14 ★) — week of Oct 5"; Endless: "Note Ninja Endless (2,340)"), the avatar's name in words, "+100 tokens" counting up, small print "Show Mr. Graham this screen: ID ab12cd" and CLAIM (yellow, focused); a new item then gets the usual UNLOCKED! card (`Skins.catchUp`). Sound `champion-fanfare` (falls back to `level-complete`; the lobby only, never while listening); confetti once (none under reduced motion or Motion off: a fade). THE TROPHY SHELF on Select Player's player card (player 1, not the guest or CPU): "🏆 3× weekly champion" under the stars, a tap lists "Week of Oct 5: Most stars (14 ★)" (`Leaderboard.trophies()`); hidden with none. THE SCREEN: "LAST WEEK'S CHAMPIONS" strip above the tabs for the grade shown (a plaque per champion: board name, avatar name in words, value, the board's icon; endless ones under their game's name; this device's plaque highlighted with YOU; empty boards left out; none at all = no strip), and a 🏆 next to any entry on this week's boards whose id was a champion last week (same grade). `?teacher`: under MY SETTINGS this device's awards (claimed / waiting), the last check (`champCheckedWeek`, ok/why) and CHECK CHAMPIONS NOW (`checkChampion({force: true})`). Words: `Leaderboard.boardName(b)` / `boardValue(b, v)` / `weekName(w)`; tests: `Leaderboard.champState()`, `ChampionLobby.state()`, `LeaderboardScreen.state()` (`plaques`, `cups`). Tests: tests/champions.spec.js (the mock's `?action=champions` is in helpers.js `boardFor`). Tests: tests/network.spec.js ('play' once per game per day, only the allowed fields), tests/leaderboard.spec.js (warm-up, simple requests, a slow board, the retry + saved board, the break message). NAMES ARE WORD NUMBERS: `Avatar.nameNumbers(av)` / `nameFromNumbers([t, a, n])` (unknown, retired or NEVER-USE = "Mystery"), `wordNumber`, `wordAt`; the numbers = each word's place (from 1) in avatar-names.js's APPEND-ONLY lists (a retired word is `'#Word'`: its number stays reserved); avatar-code.js's TABLE reads the same lists, so share codes use the same numbers (old codes decode unchanged). `Arcade.Leaderboard` (`available/settings/setGrade/setOn/canSend/board/mine/queue/flush`) and `Arcade.LeaderboardScreen.state()` for tests.
