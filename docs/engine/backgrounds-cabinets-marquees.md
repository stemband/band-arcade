# Menu backgrounds, cabinets, marquees and the 3D floor

## Menu backgrounds

- MENU BACKGROUNDS (`shared/bg-scenes.js` + `shared/backgrounds.js`, loaded right after sfx.js by every game page; `.bg-*` styles in theme.css): one fixed full-screen layer (`.bg-layer`, z-index −1, appended to body; `html.bg-on` makes the body's own background transparent while it shows) = Mat's picture (`shared/backgrounds/<id>.webp|.jpg|.png`, `<id>-portrait.*` on tall screens; misses remembered per tab in sessionStorage `bandarcade.bg-miss`; README there) ELSE the coded scene (games.js `bg: {scene, dim, focus}`) + the readability overlay (`.bg-dim`: `dim` everywhere, + `focus` in the middle). `Arcade.Bg.mount(gameId)` (mountTopbar does it), `Bg.menu(on)`: every menu screen on, play off (0.4 s crossfade; the scene keeps moving while it fades); `Sfx.gameMenuMusic` calls it, so the 9 games with menu music need nothing else; Lost Signal and Vanishing Ink call it from their `menuMusic(on)`, Dojo Duel on setup (on) / match (off), Arcade Quest in `Q.go` (the title only). Scenes: `Arcade.BgScenes.<scene>(ctx, W, H, t, {state, still, colors})` (storm, manor, bamboo, ink, vault, temple, arena, rink, stage, track, space, night-dojo, pixel-night, aurora; and, for avatar backgrounds so far, city, synthwave, galaxy, records, bubbles, lavalamp, confetti, fireflies; draw what never moves ONCE into `state` (pixel-night's dithered sky); `STILL[scene]` = the still moment; `flashes(scene, from, to)` for tests): DARK, low contrast, activity toward the edges, tokens only (`col()`/`mix()`). PHOTOSENSITIVITY: storm lightning = a glow BEHIND the clouds (`STRIKE`: every 6–15 s, 50 ms rise, 0.35–0.76 s fade incl. a 35 % chance of a weaker 2nd pulse 0.21 s later; measured ≤ 2 pulses a second, the brightest 1/96 of the screen +0.15 relative luminance, ≤ 1 % of the screen over the 0.1 flash threshold); stage `SPUTTER` = 3 smooth dips over 1.4 s every 8–13 s. PERFORMANCE: one scene, ≤ `FPS` 30, drawn at `RES` 0.6 of the screen (≤ `MAX_W` 1100 px) and scaled up, nothing while hidden or in play; frames averaging > `SLOW_MS` 40 over `SLOW_WINDOW` 3 s = still frames for good on this device (`gameData('bg').slow`); reduced motion or the MOTION switch (the Settings panel, shared/ui-kit.js: `gameData('bg').motion`) = the still frame. `Bg.state()` for tests. The ART BOARD (`art-board/index.html`, not linked): every game's scene (moving while on screen, with the overlay and a mock menu, "coded scene (default)" / "your image (overrides)"), its background / portrait / marquee slots, and every instrument portrait slot. A new game: add `bg: {scene, dim, focus}` in games.js.

## Cabinets

- Cabinets (`shared/cabinets.js` + `shared/cabinets.css`): `Arcade.cabinetHTML(game, {href})`, `Arcade.marqueeHTML(game)`, `Arcade.trimClasses(game)`, `Arcade.cabinetOf(game)` (settings with defaults), `Arcade.setAttract(cabEl, game)` (only the front cabinet animates). A CANVAS SCREEN (a `SCREENS` entry with `draw(ctx, W, H, t)` + an `html()` holding `.scr-cv canvas`, e.g. Music Highway) is drawn by the same function in 2D and 3D (`SCREENS3D[name]` calls it at 256 px): `Arcade.hydrateScreens(root)` (arcade.js, after the slots are built) draws each one's STILL frame (`t` = null), `setAttract` runs the front one's rAF loop (≤ `SCREEN_FPS` 30, dpr ≤ 1.5, nothing while hidden or `A.floorPaused`, none under reduced motion) and puts the old front back on its still frame.

- Cabinets: each game's look is its `cabinet` field in `games.js` (`shape`, `trim`, `trim2`, `marquee`, `screen`; all optional, missing or unknown values fall back to a classic cabinet). `cabinet.marquee` now picks only the title's lettering (and the 2D sign's frame shape); the picture behind it is the game's own `marquee` entry (MARQUEES below). The parts it picks from live in `shared/cabinets.js` (`SHAPES` silhouettes on a 300 × 600 grid, `SCREENS` attract loops) and `shared/cabinets.css` (trim colors, marquee lettering, screen styles). Give a new game its own silhouette/screen rather than reusing another game's whole look. Never let a missing cabinet entry break the home page.

## Marquees

- MARQUEES (`shared/marquees.js`, loaded by index.html after cabinets.js): every cabinet's lit sign is a canvas drawing: a themed animated SCENE + the title. One renderer for the 3D texture (arcade3d.js `shared.marquee`: 512 px wide, redrawn only for the FRONT cabinet at `Marquee.FPS` = 20, half that once the 3D floor has downgraded; the old front goes still on a turn), the 2D cabinets (`Arcade.marqueeHTML` = `Marquee.html`: a `.mq-live` element with a canvas + the name for screen readers; `Marquee.hydrate(root)` draws still frames; `setAttract` calls `Marquee.animate(el, 'floor')`) and Select Player (`animate(el, 'select')`, stopped by `close()`). Each game's look = its `marquee` entry in games.js `{scene, colors (theme tokens, in the scene's order), speed, still, every, titleLayouts}`. **Cabinet marquees show only the game's main title, fit as large as possible (titleFit:'max'). No subtitles, taglines or small text on marquees.** ('max' is the only mode, so a new game gets it automatically; there is no `kicker` any more; 2-player and other info goes on the lobby's cards, e.g. ALL GAMES' 2P / ASSIGNED badges beside the name, never over the picture.) `fitMax` tries 1 line or 2 stacked lines (every split at a space; never inside a word or at a hyphen: NEON / FACE-OFF; or the game's `titleLayouts`) and keeps the biggest; it measures each line's real glyph bounds (first/last letter overhangs, letter-by-letter advances, a space at least `WORD_GAP` 0.28 em because GN Neon's space is a hairline) + outline (`STROKE`) + visible glow (`GLOW × GLOW_REACH`) + slant, keeps `TITLE_MARGIN` × H + the border + 2 px on every side, all lines one size, `LINE_GAP` between them. FONTS FIRST: `fontReady(font)` = the title is measured and drawn only once its lettering font has loaded (`document.fonts.check`/`load`; until then the sign shows its scene alone; a font that never arrives falls back after `FONT_WAIT` 3 s), and `redrawAll()` redraws every 2D sign, 3D texture (`onArt`) and thumbnail the moment it arrives (and on `loadingdone`); cached per (game, W, H, font loaded), so it re-fits on resize too; `fitInfo(g, W, H)` (`{size, lines, font}`) and `draw(…, {titleOnly: true})` for tests; scenes in `SCENES` (storm, manor, vu, dojo, vault, scroll, versus, hockey, curtain, synthwave, pixel, radio, duel, ink, sparkle = the default: the game's color, moving gradient, sparkles). The title's font comes from `cabinet.marquee` (`FONTS`); it always gets a dark outline + dark haze so it stays readable. Only the front (and Select Player) animates; `prefers-reduced-motion` = still frames everywhere; nothing while the tab is hidden or `A.floorPaused`. PHOTOSENSITIVITY RULE: nothing may flash more than 3 times a second; lightning, flickers and sparks light only PART of the sign and fade in/out (storm `every` ≥ 1.2 s; flickers < 1 Hz, smooth). Test with the luminance-sampling check (WCAG 0.1 threshold) before adding a scene. MAT'S ART: `shared/marquees/<id>.png|.webp` replaces the scene (title still drawn), `<id>-full.png|.webp` the whole sign (1200 × 300 recommended; shared/marquees/README.md); misses remembered per tab (sessionStorage `bandarcade.mq-miss`); the 3D view skips pictures on file:// (a tainted canvas can't be a WebGL texture). `Marquee.onArt(g, fn)` redraws when a picture or font arrives. Colors only via theme tokens.

## 3D cabinets

- 3D cabinets: `cabinet3d` in `games.js` (`profile`, `trim`, `trim2`, `body`; all optional, defaults come from the 2D `cabinet`, so the two views always match). `arcade3d.js` holds `PROFILES` (side-view points extruded into the body, with anchors for marquee, screen, panel, door, START and a topper: `peak`/`dome`/`fins`/`pagoda`/`vault`/`gate`/`vs`/`puck`/`lamp`/`wing`/`dish`/`lanterns`/`scroll`; `dial: true` = a round safe door; `twoPlayer: true` = two joysticks and two sets of buttons; `wheel: true` = a steering wheel and gear stick), the canvas-texture marquees and attract screens (canvas versions of `SCREENS`, same loops), and the scene. `arcade.js` owns all controls and HTML; a view (2D or 3D) implements `place(cur, instant)`, `pick(event)`, `startLink`, `destroy()`. The 3D canvas is decoration (`aria-hidden`); START is a real `<a>` positioned over the front cabinet, and it does not follow the sway.
- 3D performance rules: three.js loads only when a zone opens (never for the lobby / ALL GAMES); while it loads no 2D cabinets are built (only if 3D gives up); in a zone only the front cabinet and its neighbors (within `NEAR` = 1.5 places of where the carousel is and where it's going) are FULL cabinets, farther ones a FLAT stand-in (one textured plane: silhouette + marquee + screen, `flatCab`), swapped as it turns, and cabinets beyond `VIS` (2.6 places, never visible) have nothing built; a FAST SPIN (more than `SPIN_FROM` 2.5 places, `SPIN_MS` 650: the Full Arcade's jump strip) builds full cabinets only at both ends, the ones it flies past get a flat stand-in as they come into view; `setRing(ring, wrap, cur, fade)` swaps zones and `setRing([])` (the lobby) disposes every cabinet's geometry, materials and the zone's marquee/screen textures (the renderer stays, paused by `A.floorPaused`); `stats()` adds `built`, `disposed`, `full`, `flat`. Render only while something moves (turn, sway, front attract screen), ≤ 30 fps when idle, stop when the tab is hidden; pixel ratio ≤ 1.5; no post-processing (glow = additive planes and fat translucent tubes; reflection = the ring drawn upside down under a see-through floor, without small parts or far cabinets); average frame > 40 ms over 3 s → pixel ratio 1, no haze, no sway; still slow → 2D (`destroy()` + `onGiveUp`: the renderer is disposed and NOTHING may draw again: `frame()` returns once `dead`). ONE animation loop only: a `kick()` during a frame (the downgrade's resize, a marquee picture arriving) already asks for the next frame, so `frame()` never asks again (two loops doubled the work on slow devices, and the one `destroy()` missed kept drawing with the disposed renderer: WebGL "glTexStorage2D: Texture is immutable", an error in WebKit; `tests/floor3d.spec.js`). `Arcade.Floor3D.stats()` reports frame times and draw calls. Colors come from the theme tokens (`getComputedStyle`), never hard-coded.
