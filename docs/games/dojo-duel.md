# Dojo Duel (`dojo-duel/`)

- THE UI KIT: the pause is the kit's, placed in the center strip `#midC` (`place`: both players reach it in Tabletop; RESUME · RESTART · SETTINGS · CHANGE SETUP · BACK TO ARCADE GAMES (the kit's, `onArcade` stops the loop and the dojo sounds; it replaced the old EXIT)); results = `A.UI.results.render` inside each half (REMATCH · CHANGE SETUP · EXIT). The text below describes the match itself.
- FINISHED: the end of a match (`victory()`) calls `store.noteFinished('dojo-duel')` (its results are `UI.results.render`, which doesn't): TODAY'S PRACTICE checks it off.
- Two-player note-reading race on ONE device (Band Ninja world). NO microphone (never load `pitch.js`/`mic-gate.js`); `player: 'all'` + `players: 2` in games.js (START goes straight to the game, no instrument needed), `maxStars: 0`, no effect on Note Ninja progress; the floor shows `summary` (the dojo record).
- SETUP (remembered in `gameData('dojo-duel').setup`): mode 2 PLAYERS | SOLO VS. SENSEI (Easy/Medium/Hard = `DUEL_SENSEI`: react s ± spread, wrong-tap chance); match length 7/10/15 (`DUEL_RULES.lengths`); layout TABLETOP (default on touch screens) | SIDE BY SIDE. Each player: avatar (Player 1 = the device's avatar, Player 2 = the GUEST avatar: EDIT opens `AvatarCreator` with `guest`, SURPRISE ME re-rolls it), name ("Player 1"/"Player 2" by default, or the avatar's safe name), clef (treble/bass; no alto: no instrument reads it), NOTES (First 5 / the four scales / Chromatic, labeled by their written key), and BELT = any Note Ninja belt with a star on this device (`bestLevelStars('note-ninja', …)`, any instrument) or the next one; all in `?demo`. Belts are the handicap: each player's notes = `buildSequence` with THEIR belt's `pool` (White = the smaller pool), `guides` (`staffGuides`) and `relabel` from `note-ninja/levels.js` `NINJA_BELTS` (loaded, never copied). Notes are written for the saved instrument if it reads that clef, else trumpet (treble) / trombone (bass). The Sensei reads Player 1's kind of notes. A key map shows the keyboard groups.
- A POINT (`M.phase` 'count' → 'play' → 'result'; every timing in `DUEL_PACING` at the top of levels.js): COUNTDOWN (`countdown()`; its beats and sounds come from `shared/countdown.js`, voicePrefix 'dojo', on the game clock): pads locked + `.waiting` (dimmed a little), empty staffs, 3-2-1 in each half's `.hf-call` (so each reads upright for its player in Tabletop), scale-in only; SOUNDS: CLASSIC = the spoken `dojo-count-3`/`-2`/`-1` on each number, QUICK = the `dojo-count` tick, OFF = none. Style = setup `S.count` 'quick' (`quickStep` 350 ms) | 'classic' (`classicStep` 1 s) | 'off' (`offMs` 0.4 s gap, no numbers), remembered in `setup`; MATCH START (and REMATCH): once `Sfx.whenReady(COUNT_SOUNDS, 800)` (the setup screen `Sfx.preloadScreen('dojo-duel')`s every dojo-*/sensei-* sound) and no voice is still speaking, the gong `dojo-begin` + the Sensei's `sensei-begin` + "Begin!" together, then the first note's CLASSIC 3-2-1 `introGapMs` 0.4 s after the longer ends (≤ `introMaxMs` 3 s, never while the Sensei speaks; `M.introMs`); the first note of a match is always CLASSIC, so voices never overlap, and so is the note after a point that leaves someone at match point (`M.tense`). Then `showNote()` draws both notes and unlocks both pads in ONE call inside the game-clock rAF tick (same frame), `pt.t0` = now (the Sensei's reaction starts here), `dojo-count-go` ("Go!", every style; falls back to `dojo-reveal`, never both). Answers = `it.n` (letter + acc, as Note Ninja); taps outside 'play' do nothing. First correct tap wins: correct taps are collected for `tieMs` and the smallest `ev.timeStamp` wins (multi-touch pointerdown). A wrong tap = `stunMs` (1 s) dizzy: pad locked + swaying, avatar with orbiting stars; the other player keeps going. Both wrong, or `noteMs` (6 s) with no answer = no point. RESULT MOMENT (`endPoint`, `resultMs` / `noPointMs` 1.5 s, pads locked): both notes gold/coral with the name next to them, the right button `.good.answer` on both pads, a wrong tap stays `.bad` + "You tapped G. It's E."; a point = the winner's half `.won` (belt-color glow), their ninja `.strike` toward the other (`--sx/--sy` per layout), the other `.stagger`, "+1" flies to their score (`flyPoint`, layout positions via `centerIn`, `flyMs`; reduced motion: no flight), "POINT!" + a Sensei line, `dojo-strike` + `dojo-point` (+ `sensei-fast` / `sensei-point`, below); nobody = "Too slow, ninjas!" / a both-wrong line + `dojo-no-point`. MATCH POINT: the `.mpb` banner on that half during the result moment + the center line + that half's tag; the winning point goes straight to the victory screen after its result moment. The clock is a game clock (stops on PAUSE, Esc, a hidden tab). No power-ups.
- LAYOUTS: `.duel` is fixed full screen (`touch-action: none`; gesturestart/dblclick/contextmenu/selectstart and touchmove prevented; nothing scrolls or zooms). TABLETOP = top/bottom halves, the top half (Player 2) `rotate(180deg)`, the center strip's 2P score rotated too; if the device turns during a match, `holdOrientation()` counter-rotates the whole duel so the halves stay with their players (and the setup note suggests Rotation Lock). SIDE BY SIDE = left/right, both upright. Solo = side by side in landscape, stacked upright in portrait. Results render INSIDE each half (so the top one faces its player): VICTORY!/WELL FOUGHT!, both ninjas bowing, accuracy, average answer time, the dojo record, PRACTICE THESE (up to 4 notes: wrong taps, then no answer, then lost, then slowest, on a mini staff in their clef), REMATCH / CHANGE SETUP / EXIT.
- Keyboards: Player 1 Q W E R T Y U = A–G, A = ♭, S = ♯; Player 2 1–7 = A–G, 8 = ♭, 9 = ♯ (tap the sign first, like the buttons; every belt works). Solo: both groups play for Player 1.
- Saved: `gameData('dojo-duel')` = `{setup, record: {'<player name>': wins}, sensei: {easy|medium|hard: {w, l}}}` (in the Arcade Backup Code with all gameData). The Sensei's lines = `DUEL_LINES` in levels.js (kind to both players).
- Sounds (mic: false, pitched is fine): `dojo-music` (setup), `dojo-match-music` (match), `dojo-begin` (the gong at every match start, with sensei-begin), `dojo-count` (the QUICK tick), `dojo-count-3`/`-2`/`-1` (spoken CLASSIC numbers, fallback `dojo-count`), `dojo-count-go` (the reveal, fallback `dojo-reveal`; ONE FILE PER WORD, trimmed to start at once, numbers < 0.8 s; nothing ever stops a sound: every play is its own source), `dojo-strike` (the winner's strike), `dojo-no-point`, `dojo-point`, `dojo-wrong`, `dojo-match-point`, `dojo-victory`; the Sensei's voice (short generated jingles until recorded): `sensei-begin` (every match start, with the gong, before the first 3-2-1), `sensei-fast` (after a PLAYER's point won in under `DUEL_PACING.fastMs`, any mode), `sensei-point` (ONLY Solo, when the computer Sensei scores; never both with sensei-fast), `sensei-victory` (every match end). NO TWO VOICES AT ONCE, NOTHING LEFT OVER: a point's effects are `Sfx.sequence([...], 80, {channel: 'dojo', maxStep: 900})` (strike, point, match-point) and its Sensei line a separate `'dojo:voice'` sequence (starts with the strike, after any "Go!"; not on the match-winning point: sensei-victory follows); a countdown waits (`voiceWaitMs`) until the voice lane is done and no voice speaks (a match-point countdown also waits for the MATCH POINT sound to start); victory, REMATCH, Setup and Exit call `Sfx.cancelAll('dojo')` (+ `Sfx.hush()` on leaving/rematch).
- Look: `--dd-*` tokens (night, wood, paper lanterns), belt-color headbands on the avatars (`.band`), the neon center line; reduced motion = no bob/jump/dizzy/bow/sway. Cabinet: `shape: 'duel'` (dojo roof, two-player panel, lanterns), `screen: 'duel'`, marquee scene `duel` (lanterns, crossed bamboo, belt ribbons; font GN Neon), 3D profile `duel` (`twoPlayer`, topper `lanterns`). `?demo`: every belt open, the answers under each staff; `Arcade.Duel.state()` (incl. `phase`, `countKind`) / `setup()` / `rotate(angle)` / `tap(pi, letter, timeStamp)` for tests.
