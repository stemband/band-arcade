# Note Ninja (`note-ninja/`)

- Note identification with NO microphone: never load `pitch.js` or `mic-gate.js` there, never ask for the mic. It loads `sfx.js` and plays the named events.
- NOTES × ORDER like every note-reading game (`Arcade.ModePicker`). The right answer is the note's real name, key signature included (a B in F major is B♭, in Random and Scale Order alike), spelled as shown (C♯ ≠ D♭). Answer pad (its own markup, the shared rule: [notes-and-scales.md](../engine/notes-and-scales.md) THE NOTE-NAME ANSWER PADS): First 5 and the scales = THE SPELLED PAD (`G.spelled`, the WHOLE set's names from `seq.spelled` / Endless's full set: one button per note, "B♭ C D E♭ F", one tap; no ♭ ♮ ♯ row; `#pad.sp`, `--cols` from `AnswerPad.cols`); CHROMATIC (or the teacher setting `SPELL_ANSWER_BUTTONS` off) = the Shift pad: ♭ ♮ ♯ act as a Shift for the next letter (♮ default, resets after each letter; shown only when the level's notes have any accidentals), then A–G, and `relabel: false` (Diamond, Endless's no-hints) only matters there. Keys A–G (a spelled pad: that letter's spelled note) and 1/2/3 (Shift pad only) on Chromebooks. A wrong tap says "Not E♭." `?demo` shows the answer (spelled) under the buttons.
- Belts = levels in `note-ninja/levels.js` (`NINJA_BELTS`: name (one of `shared/belts.js`, which supplies the color and sparkle), count, time, guides, onStaff for read-ahead, pool, `relabel: false` = the letter buttons don't show ♭/♯ after the Shift). They are Mat's 10 Band Ninja ranks, in order: White, Yellow, Orange, Green, Blue, Purple, Red, Brown, Black, Diamond (`maxStars` 30). Belt colors are `--belt-*` tokens in theme.css. Progress is saved by belt number, so never reorder or insert belts without a one-time migration in `storage.js` `migrate()` (flagged in `data.migrated`; `ninja-10-belts` moved old 8 → 9 and 7 → 8 when Red was added). Unlocking = the previous belt has a star, or the belt itself already has stars. Scoring and stars are in `NINJA_RULES`. Progress: the PROGRESS KEYS table (`note-ninja`, `note-ninja:scale-<id>`, `note-ninja:random-<id>`, `note-ninja:order-first5`…); the `ninja-10-belts` migration moved every key that is `note-ninja` or starts with `note-ninja:`, so any key saved since is already in 10-belt order.
- RARE DIAMOND GEAR: the game itself is unchanged (any note set clears the Diamond belt and its stars count as before), but five rewards need the Diamond belt on CHROMATIC notes in RANDOM order (the progress key `note-ninja:random-chromatic`): the Diamond headband (head `diamondband`), the Diamond belt headband (head `belt-diamond`), the Diamond belt name plate (plate `belt-diamond`), the Bamboo Moon background (bg `bamboomoon`) and the Diamond color skin (skins.js `diamond`). Rule text: "Earn the Diamond belt in Note Ninja on Chromatic notes, Random order" (avatar-parts.js `NINJA_DIAMOND`, the rule's `key` field: [avatars.md](../engine/avatars.md)). Belts White–Black (and the White / Black ninja gi) still unlock with any note set. Devices that earned them before the change keep them (storage.js migration `ninja-diamond-chromatic` made them owned). The Diamond belt card (game.js `rareGear()`) has a small line under its blurb, "Rare gear: earn it on Chromatic + Random!", with a tiny picture of each piece (the player's avatar wearing it, the plate's frame, the skin's glow; `.rare*` in style.css), so students know the challenge exists. Tests: tests/ninja-diamond-gear.spec.js.
- ENDLESS (`G.endless`, the ∞ card, `NINJA_ENDLESS` in levels.js): SPEED 1 = the White belt (10 s a note); time per note = time1 ÷ SPEED (never under `minTime`), set when each note starts; at each new group the guides fade, read-ahead grows (`readAhead`) and the button hints stop (`noHintsFrom`); the ninja's belt follows the pace. The run clock only counts while a note waits for an answer. A wrong answer or a timeout = a heart (the note turns red, the run moves on). Notes come in chunks from `ModePicker.sequence` (the smaller pool until `smallPoolUntil`, then the whole set: never a note outside it). `A.Ninja.state()` for tests.
- THE SENSEI BESIDE THE STAFF (game.js `drawGroup` / `pose` / `slice`): the Sensei (`A.senseiSVG`) stands INSIDE the scroll, in a slot at the right end of the staff drawing (`SENSEI_W` units, the drawing's full height, `#nnSensei`): the drawing keeps the width it always had (`[290, 330, 380, 420][onStaff] + key signature`), the staff lines stop before the slot and the notes share the rest, so nothing is drawn smaller and he never covers a note (read-ahead too), the clef, the key signature or the guides. He wears the belt (the level's `L.color`, Endless's pace belt). Poses: 'ready' while you read, 'strike' on a right answer, 'hmm' on a wrong answer or a timeout (`POSE_MS`, then 'ready'). THE SLICE (`slice(k, big)`): a bright streak along a rising cut through the note head, the note (gold) split into two clipped halves that slide apart and fade (`SLICE_MS` 300; a combo milestone = a longer, golden streak, plus the combo pop); the note itself is gone, its gold name stays. It never delays anything: the next note and the timer start exactly when they always did (read-ahead at once, a new group after `afterGroupMs`), the halves fade on top. Reduced motion / MOTION off: no sliding, no moving streak (the note splits in place and fades), poses change without the lunge. A wrong answer shakes the scroll (not under reduced motion). The results hero is the Sensei ('happy' with stars, else 'calm', in the belt). The staff stays large and still. `A.Ninja.sensei()` (the pose) for tests: tests/note-ninja-sensei.spec.js. (`A.ninjaSVG`, the old mascot, is still in ui.js; Note Ninja no longer shows it.)
